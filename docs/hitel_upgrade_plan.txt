0. 장별 학습 요약 및 수확
--------------------------------------------------------------------------------
1~2장 (PC통신 개론/모뎀·프로토콜, p.5~18):
   하드웨어·AT명령 시대 배경. 웹 재현에 직접 적용할 기능 없음.
   수확: 접속 연출 소재(ATDT 01410, 2400/9600/14400bps 노드, CONNECT).
3장 (이야기 통신 에뮬레이터, p.19~62):
   갈무리(핵심!), 문서 편집기, 상태창(자판·코드·속도·갈무리 상태), 환경설정.
4장 (가입/접속/요금, p.63~80):
   온라인 가입 절차(우리 signup과 정합), 접속 초기 화면의 [작은공지]+GO 링크.
5장 (첫 나들이, p.81~96): 메뉴 체계, 기본 명령어(HI/H/X/Z/GO/T/P/M/F/B/A/N),
   환경 구축(go abc: 비밀번호·초기화면·화면 표시 등급·전자사서함 확인).
6장 (대화실, p.97~102): 대기실 상황판(ST), 귓속말(/TO), 방 개설 옵션.
7장 (전자우편, p.103~121): 편지 종류 8종, 발송 명령 6종, 보낸편지 수신확인,
   발송 취소(CM), 부재 통지(ABSENT).
8장 (게시판, p.122~138): PT(제목 100건 일괄), LS/LD(번호·날짜 검색), K/KW(주제어),
   PR 다중·범위 연속읽기.
9장 (동호회, p.139~146): 회원 레벨, 손님 인사 배너.
10장 (공개자료실, p.147~153): DN 프로토콜 선택 연출, 전송(다운로드 수) 컬럼,
   업로드 절차(검색어 3개), 자료실 메모판.

■ Phase 1 — 저위험 고감성 (즉시 착수 가능)
--------------------------------------------------------------------------------
P1-1. PT [번호] : 제목 100건 일괄 출력 + 원전 연출                    [소~중]
   책: p.133-134. `>> pt 9999` → "PRINTER/CAPTURE 를 준비하시고 Enter를
       누르십시오" → 지정 번호부터 100건 제목 연속 출력.
   현황: CMD_META에 PT 없음. 뉴스 _printView(전체 펼침) 패턴 재사용 가능.
   구현: post-list/pds에서 PT [번호] → 원전 안내문 → 엔터 → 제목 일괄 화면
        (엔터로 목록 복귀). commandRouterBrowse + 전용 빌더.
P1-2. PR 다중·범위 연속읽기 (PR n-m / PR n,m,... 최대 10건)            [소]
   책: p.136 명시 스펙.
   현황: commandRouterBrowse.js:271 `PR [단일번호]`만. 이후 빈 엔터 연속은 있음.
   구현: 파서 확장 + 연속읽기 큐(state._prQueue). 종료 시 기존 "연속읽기를
        마칩니다" 힌트 재사용.
P1-3. 동호회식 신분 배너 "## OOO님은 손님입니다 ##"                   [소]
   책: p.152 원문 그대로.
   현황: 게스트 개념 전면 존재, 배너 없음.
   구현: 게시판/자료실 목록 첫 진입 시 1회 한 줄 배너(게스트=손님, 로그인=
        정회원). 화면당 세션 1회로 소음 방지.
P1-4. 메인 진입 [작은공지] 줄 + GO 링크                                [소]
   책: p.69(그림 4.4) 접속 초기 화면의 [작은공지] — GO 인덱스가 괄호로 붙는
       공지 1~3줄 (예: "예비동호회 20개가 새롭게... (GO FORUM)").
   현황: 메인 화면에 공지 줄 없음.
   구현: 관리자 게시판(공지) 최신 1~2건 제목을 메인 상단/하단 한 줄로,
        (GO PLAZA) 식 클릭 가능 토큰과 함께. txt 자산 or API 재사용.

■ Phase 2 — 원전 상징 기능 (핵심 재현)
--------------------------------------------------------------------------------
P2-1. 세션 갈무리(CAP) 토글 — '갈무리 중' 상태 표시                    [중]
   책: 3장 전반(p.44, 51) + PT/PR과의 병용 문화(p.133). 이야기의 상징 기능.
   현황: 뉴스 한정 PR 갈무리만 존재. 세션 누적 캡처 없음.
   구현: CAP 토글 명령 → 이후 모든 렌더 화면의 플레인 텍스트 누적 → 종료 시
        .txt 다운로드+클립보드. 상태 영역 '갈무리 중' 뱃지(기각된 연결시간
        표시와 달리 기능 상태 피드백이므로 미학 충돌 없음).
        렌더 후킹: terminalSequentialRenderer 완료 지점 1곳.
P2-2. 보낸쪽지함 + 수신확인(수신/않읽음)                               [중]
   책: p.113, 122 "전자 우편의 편리함 중의 하나가 바로 보낸 편지를 확인".
       그림 7.7: 수신자ID/수신자명/수신·참조/상태(않읽음)/일자.
   현황: 서버 스키마(isRead, senderUserId)와 접근권한(발신자 열람 허용)은
        이미 존재. listForUser가 받은함 전용인 것만 확장하면 됨.
   구현: GET /api/memos?box=sent + 쪽지함 S(보낸쪽지) 토글 + 상태 컬럼.
        2단계(선택): 않읽음 한정 CM n(발송 취소, p.122).
P2-3. 대화실 대기실 상황판(ST) 재현                                    [중]
   책: p.103(그림 6.1) — 대기실 인원 명단 + "(개설방수: n/100 현재참여인원:
       m명)" + 방별 `#번호 공개(인원) [개설자] 방제목` 목록, J n 입장.
   현황: 로비는 접속자+방 이름 나열뿐. 방별 인원/개설자/공개여부 없음.
   구현: chatAnsiBuilders 로비 레이아웃 재구성 + 방 목록 API에 인원·개설자
        노출 + ST/J 별칭.
P1~P2 공통 검증: Playwright 헤드리스(데스크톱 1280 + 모바일 360 터치),
        node --check(ESM), smoke:renderer-ui / smoke:boards / smoke:chat-rooms.

■ Phase 3 — 환경 구축(go abc 계열) 및 명령 확장
--------------------------------------------------------------------------------
P3-1. 화면 표시 등급 (초급/중급/고급)                                  [중]
   책: p.94 "초급은 기초적인 것들만 표시, 중급은 대부분 표시, 고급은 어떠한
       명령어도 표시하지 않는다".
   현황: 자동 트리밍+H 툴팁 집약(사용자 확정 설계)이 사실상 '중급'.
   구현: SET LEVEL 초급|중급|고급 (envVars, SET 수정 20260711_2340로 인프라
        완비). 초급=우선순위 상위 N개, 중급=현행, 고급=H만 or 완전 숨김.
        ※ 기본값은 반드시 현행(중급) 유지 — 힌트바는 사용자 결정 누적 영역.
   주의: 구판 계획서의 "go abc 가상 콘솔 화면"은 SET 한 줄이면 되는 것을
        전용 화면으로 만드는 과설계 — TUI 폼 화면은 사용자가 원할 때만.
P3-2. LS [번호] / LD [월/일] — 번호·날짜 기준 목록 점프                [중]
   책: p.130-131. LT/LI와 함께 하이텔 검색 4종 세트.
   현황: LT/LI만 구현.
   구현: 클라 계산(페이지 산출)으로 1차 구현 가능. CMD_META 등록.
P3-3. 초기 화면 설정 (SET HOME [인덱스])                               [소]
   책: p.93 "초기 화면으로 설정하면 접속 후 곧바로 원하는 화면을".
   현황: 없음. resolveBoardTarget(한글 매칭) 재사용 가능.
   구현: 로그인/부팅 완료 훅에서 HOME 존재 시 자동 GO. UNSET HOME 해제.
P3-4. 귓속말 /TO userid [msg]                                          [대]
   책: p.110 "잠수" 문화. /TO id msg 한마디형 우선.
   현황: 없음. 서버 메시지 모델에 targetUserId + 조회 필터 필요.
P3-5. K [주제어] / KW — 주제어 검색 (1단계: 말머리 근사)               [중]
   책: p.134-135. 1단계는 제목 [말머리]를 주제어로 간주(스키마 무변경),
       2단계(보류): keywords 컬럼.
