# 01410 공통 개발 원칙

이 문서는 `docs/`의 PC통신 원전·복원 자료와 현재 `www-bbs` 구현에서 반복적으로 확인되는 공통 규칙을 정리한 개발 계약이다. 원전의 모든 기능을 복제한다는 뜻이 아니라, 현재 웹 서비스에 적용할 수 있는 안정적인 공통 동작을 정의한다.

## 1. 명령어 중심 이동

- `GO <keyword>`는 화면 어디서나 사용할 수 있는 전역 이동 명령으로 취급한다.
- `P/M/B/N/A/F/L/T` 등 짧은 명령은 현재 화면의 문맥을 우선한다.
- 긴 명령(`PREV`, `MAIN`, `NEXT`, `READ`, `WRITE` 등)은 검증된 짧은 명령으로 정규화한다.
- 지원하지 않는 원전 키워드는 임의의 화면에 연결하지 않고 보류 목록으로 남긴다.

## 2. ANSI 터미널 화면 구조

- 상단 서비스명·화면 제목, 고정폭 본문, 페이지/번호 표시, 하단 명령 힌트의 순서를 유지한다.
- ANSI/CSI 제어열은 현재 renderer가 안전하게 처리할 수 있는 범위만 지원한다.
- CP949/Johab 및 Nurie `.NRE` 자료는 원본 참고자료로 보존하되, 웹 화면에 직접 실행하지 않는다.
- 해석하지 못한 제어열은 텍스트를 깨뜨리지 않도록 무시하거나 안전하게 제거한다.

## 3. 입력 parity

- 클릭·터치 가능한 모든 명령은 키보드 입력으로도 실행할 수 있어야 한다.
- 키보드 전환(`Tab`, 화살표, `Enter`, `Escape`)은 명령어 문자열을 임의로 입력창에 주입하지 않고 실제 focus/action으로 처리한다.
- 버튼과 핫스팟에는 접근 가능한 이름과 키보드 focus 상태를 제공한다.
- 한 화면의 동일 동작에 대해 마우스 이벤트와 키보드 라우팅을 별도 로직으로 복제하지 않는다.

## 4. 본문·힌트·오류 영역 분리

- 입력 프롬프트와 필드별 검증 오류는 해당 본문 흐름 안에 표시한다.
- 하단 힌트바는 전역 이동·저장·취소 안내를 유지하며 오류 메시지로 덮어쓰지 않는다.
- 힌트 토큰이 클릭 가능할 때에도 원래 단축키의 의미와 순서를 보존한다.

## 5. 서비스 문맥 보존

- 게시판, 전자우편/쪽지, 자료실(PDS), 대화실은 공통 명령을 공유하되 문맥별 의미를 우선한다.
- 원전의 메뉴·명령을 추가할 때 현재 서비스에 실제 대응 화면/API가 있는지 먼저 확인한다.
- 전자우편과 내부 쪽지는 수신자·읽음 상태·보관함 의미를 유지하고, 시삽 건의는 외부 메일과 내부 쪽지 저장을 혼동하지 않는다.

## 6. 저장소와 보안 경계

- 브라우저에는 publishable/anon 키만 노출하고 service-role 키는 서버 환경변수로만 사용한다.
- Supabase 테이블은 서버 repository 경계를 통해 접근하며, RLS와 실제 public/authenticated 권한을 함께 점검한다.
- 보안 advisor 경고는 의도된 서버 전용 테이블과 실제 공개 데이터 경계를 구분해 처리한다.
- 스키마·권한 변경은 재현 가능한 migration과 운영 검증을 함께 남긴다.

## 7. 모바일 제약

- ANSI 고정폭 시각 체계를 유지하되 본문·제목·긴 문자열은 viewport 밖으로 넘치지 않게 줄바꿈한다.
- 터치 대상은 최소 24px을 목표로 하며, 인접 핫스팟이 서로 겹치지 않아야 한다.
- 모바일 검증은 320/360/390/430px touch viewport와 실제 라우트 순회로 확인한다.
- 데스크톱 레이아웃을 모바일에서 임의로 재배치하지 말고, 화면 문맥과 명령 흐름을 우선 보존한다.

## 적용·검증 순서

1. 관련 원전·카탈로그에서 근거를 확인한다.
2. 현재 화면·라우터·repository에 이미 있는 동작을 찾는다.
3. 재현 가능한 차이만 최소 범위로 수정한다.
4. 관련 smoke와 `npm run loop:verify`를 실행한다.
5. Production 배포는 별도 승인 후 수행한다.
