다음 작업을 이 저장소에서 이어서 수행해 주세요.

[목표]
`public/js/app.js`를 아주 작은 단위로 안전하게 모듈화하고 싶습니다.
이전에는 한 번에 크게 분리하다가 브라우저 import/export 오류가 나서 프런트가 깨졌습니다.
그래서 지금은 "부팅 경로를 건드리지 않는 작은 분리 1개 -> 즉시 검증" 방식만 허용합니다.

[반드시 먼저 읽을 것]
1. `AGENTS.md`
2. `WORK_LOG.md`
3. `public/js/app.js`
4. `public/js/core/commandFooter.js`

[현재 상태 요약]
- 프런트는 한 번 복구되었습니다.
- `public/js/app.js`는 현재 다시 동작하는 단일 엔트리입니다.
- 최근 1차 안전 분리로 `public/js/core/commandFooter.js`가 추가되었습니다.
- 이 모듈에는 다음 helper만 분리되어 있습니다.
  - `loadAssetText`
  - `parseCommandFooter`
  - `looksLikeCommandFooter`
- 현재 검증 통과 상태:
  - `npm run smoke:vercel-ready`
  - `npm run smoke:boards`
- 최근 작업 기록은 `WORK_LOG.md` 상단의
  - `20260410_1720`
  - `20260410_1735`
  - `20260410_1755`
  를 보면 됩니다.

[중요한 배경]
- 과거에 `app.js`를 대규모 import 구조로 바꿨다가 브라우저가 깨졌습니다.
- 특히 export 누락 때문에 다음과 같은 오류가 났었습니다.
  - `does not provide an export named 'loadAssetText'`
- 따라서 이번에는 절대 대규모 분리 금지입니다.
- `showSignup`, `handleCmd`, 네비게이션 전체, 인증 전체를 한 번에 분리하지 마세요.

[절대 금지]
- `public/js/app.js`를 여러 import로 한꺼번에 갈아엎는 작업
- `showSignup()` 대규모 분리
- `handleCmd()` 대규모 분리
- 메뉴 네비게이션 전체 분리
- 동작 확인 없이 여러 파일을 연속으로 쪼개는 작업
- 요청 범위 밖 리팩토링

[이번에 해줬으면 하는 정확한 작업]

후보 1. 가장 추천

- `getCommandFooterText()`
- `getSupportedFooterText()`

원칙:

- import/export 이름은 단순하고 명확하게 유지

[작업 범위]

  - `public/js/app.js`
