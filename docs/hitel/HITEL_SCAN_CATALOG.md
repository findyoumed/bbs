# 하이텔 스캔 자료 학습 카탈로그

이 문서는 `docs/hitel`에 보관된 하이텔 화면 구성·명령어 스캔을 프로젝트에서 재사용할 수 있도록 정리한 catalog입니다.

## 1. 원본 범위와 판독 방법

- 원본: `docs/hitel/*.jpg` **93개** (파일명 시간순으로 촬영된 순서)
- 책의 장 번호가 보이는 첫 묶음은 `제5장 하이텔(HiTEL)`이며, 본문 쪽수는 사진에서 읽히는 범위만 기록했습니다.
- 가로로 촬영된 4032×2268 사진은 세로로 회전해 판독했고, 1080×1920 사진 4장은 원본 방향 그대로 판독했습니다. 원본 파일은 변경하지 않았습니다.
- 흐리거나 책등에 가려진 문자는 추측하지 않고 `[판독 보류]`로 남겼습니다.

## 2. 원전에서 확인한 UI 규칙

### 접속·초기 화면

1. 접속 인사말 다음에 `[작은공지]`가 나오고, 공지 한 줄마다 `(GO 코드)`가 붙습니다.
2. 화면은 서비스명/페이지 표시, 고정폭 본문, 하단 통신 상태줄의 세 층으로 나뉩니다.
3. 하단 입력은 `번호/명령(H,P,T,GO,HI,Z,X) >>`처럼 본문과 분리된 프롬프트입니다.
4. 메뉴 번호를 입력하는 흐름과 `GO 영문코드`로 같은 메뉴를 바로 여는 흐름은 동등합니다.
5. `Y/N` 확인에서는 `Y`·`N`뿐 아니라 Enter가 기본 선택으로 동작하는 설명이 반복됩니다.

### 목록·본문 화면

- 목록 헤더에는 서비스명, 현재/전체 건수, 페이지가 함께 표시됩니다.
- 게시판 목록의 기본 열은 `번호, 이름, ID, 날짜, 조회, Pg, 제목` 형태입니다.
- 메일 목록의 기본 열은 `No., 발신자 ID, 이름, 발신일, 형태(TXT/BIN), 크기, 제목`입니다.
- 뉴스 목록은 `No., 일자, 시간, 면수, 제목` 열을 사용합니다.
- 긴 본문은 여러 화면으로 나누며 `F(다음), B(이전), P(상위), T(초기), GO` 명령을 하단에 노출합니다.
- 상태줄에는 키보드 종류, 연결 시간, 단말/전송 속도, 갈무리 상태, 시각이 표시됩니다. 웹에서는 이를 장식용 고정 상태영역으로만 재현하고 실제 모뎀 동작을 가장하지 않습니다.

### 입력·전송 화면

- 메일 쓰기는 수신자 → 참조 → 제목 → 작성 방법(에디터/Kermit/Zmodem/SuperKermit) → 본문 → 발송/저장 순서입니다.
- 편집기는 `Ctrl+Z` 종료, `E` 저장, `Q` 취소, `H` 도움말을 명시합니다.
- 바이너리 파일은 본문에서 읽지 않고 다운로드(DN)로 처리하며, 전송 프로토콜 선택과 파일 수신 준비가 별도 단계입니다.
- 자료실 업로드는 파일명·프로토콜·제목·자료 설명·분류·주제어·최종 전송 확인의 순서입니다.

## 3. 5.5 하이텔 명령어 원전 표

스캔 12번 사진(본문 쪽수 5.5 명령어 표)에서 다음 분류를 확인했습니다.

| 분류 | 원전 명령어 |
| --- | --- |
| 일반 | `H`, `X`, `Z`, `HI`, `FI`, `ME`, `MM` |
| 이동 | `GO`, `T`, `P`, `M`, `F`, `B`, `A`, `N` |
| 전자우편 | `RE`, `FR`, `AP`, `CM` |
| 검색·전송 | `LS`, `LD`, `LI`, `LT`, `LA`, `PT`, `K`, `KW`, `PF`, `PR`, `DN`, `UP`, `OD`, `CK`, `LN` |
| 대화실 | `ST`, `O`, `J`, `IN`, `WH`, `FI`, `PF`, `TO`, `Q`, `EX`, `US` |
| 주소록 | `E`, `DD` |
| 바둑 | 바둑 서비스 안에서 `H`를 입력하면 별도 명령 표를 표시 |

메일 장에서 추가로 확인한 실제 사용 예는 `RMAIL`(받은 편지), `WMAIL`(편지 쓰기), `CMAIL`(보낸 편지 확인/취소), `MBOX`(보관함), `GROUP`(단체 수신자), 비밀편지, BIN/TXT/VTX 구분입니다. 현재 프로젝트의 `ME/MEMO/RMAIL`, `WMAIL`, `CM`, `FW`, `GRP` 계열과 의미가 겹치므로 신규 명령을 만들기보다 기존 canonical 명령과 alias를 우선 유지합니다.

## 6. 현재 프로젝트와의 대조

확인한 구현 접점은 다음과 같습니다.

- `public/js/core/commandService.js`: H/P/T/M/GO/F/B/A/N, 메일·채팅·검색·자료전송 명령의 canonical metadata와 로그인 요구 조건을 보유.
- `public/js/core/commandNormalizer.js`: `GO` 인자, 페이지 이동, 메일/게시판/채팅 화면별 문맥 정규화와 한글 별칭을 처리.
- `public/js/core/historicalGoAliases.js`: 원전·타 서비스의 GO 키워드를 현재 canonical route로 매핑.
- `public/js/core/commandFooterText.js`: 화면별 하단 힌트를 정의하므로 원전의 `번호/명령` 규칙과 직접 대조할 수 있음.
- `public/js/core/ansiBoardBuilders.js`, `authScreens.js`: 작은공지/GO NOTICE를 초기 인증 화면의 본문 영역에 배치하는 현재 정책과 연결.

### 보존할 차이와 후속 후보

1. 실제 모뎀 전송(X/Y/Kermit/Zmodem), 과금, 주민번호 기반 특화 대화실은 웹 서비스 범위가 아니므로 에뮬레이션하지 않습니다.
2. 원전 명령 중 현재 기능이 없는 `LA`, `OD`, `CK`, `LN`, `AP`, `WH` 등은 문서에만 기록하고, 동등한 웹 기능이 정의되기 전에는 임의 라우팅하지 않습니다.
3. `RMAIL/WMAIL/CMAIL/MBOX/GROUP`, `PT/LD`, `ST/EX`처럼 현재 기능과 의미가 겹치는 항목은 새 화면을 추가하지 않고 기존 handler의 alias/문맥 테스트로 회귀를 보강하는 것이 우선입니다.
4. 모바일에서는 고정폭 열을 축소해 내용을 숨기지 말고, ANSI 셀 단위 줄바꿈·가로 스크롤 경계·하단 프롬프트 분리를 유지해야 합니다.

## 7. 재검증 규칙

- 원본 추가/교체 시 이 문서의 93개 인덱스와 묶음 번호를 함께 갱신합니다.
- 명령어 동작을 변경할 때는 `commandNormalizer`, 화면별 router, footer metadata를 함께 대조합니다.
- 기능 변경 없이 문서만 갱신한 경우에도 `npm run check`와 `npm run loop:verify`를 실행해 기존 동작이 보존되는지 확인합니다.
