1. 문서 목적

이 문서는 기존 CMD_UPDATE_PLAN.txt의 방향을 유지하되, 실제 구현 상태와
참조 문서, 그리고 과거 PC통신 관례를 다시 대조해서 "어느 부분을 어떻게
바꿔야 하는지"를 개발 착수용 수준으로 상세화한 최종 계획서다.

이번 개정의 핵심 목표는 아래 4가지다.

1) www-bbs 사용자 문서와 실제 구현의 명령어 체계를 하나로 맞춘다.
2) Unix/DOS 냄새가 나는 명령어와 PC통신식 명령어를 분리해서 표준안을 세운다.
3) 현재 이미 일부 반영된 새 체계와, 아직 남아 있는 구 체계를 정리한다.
4) 문서 수정, 코드 수정, 테스트 수정의 범위를 한 번에 정리한다.

2-3. 외부 관찰 근거

외부 자료는 세 통신망 공통의 GO 이동 관례를 확인하는 용도로만 사용한다.
직접 인용이 아니라 관찰 근거로만 반영한다.

- 하이텔 관련 기사에서는 "go photo", "GO COMPAC", "go edcenter" 형태가 확인된다.
  출처 예: 전자신문 1995-07-28, 1998-01-26
- 천리안 관련 기사에서는 "go askdev", "go STARLIVE" 형태가 확인된다.
  출처 예: 전자신문 1998-11-09, 2001-05-09
- 나우누리 관련 기사에서는 "go PHOTO", "go NOWRO" 형태가 확인된다.
  출처 예: 전자신문 1998-04-25, 2000-08-29

2-4. 참조 문서에서 추출된 공통 교집합

coroke, ezbbs, olddos를 비교하면 아래가 가장 안정적인 교집합이다.

- T : 초기 화면
- P 또는 M : 이전 화면 / 상위 메뉴
- C : 도움말 또는 명령어 안내
- GO [이름] : 바로 이동
- USER / WHO 계열 : 사용자 조회
- Enter : 다음 페이지 또는 다음 화면
- A / N : 게시글 연속 읽기
- O 또는 C : 대화방 개설
- /Q, /QUIT 계열 : 대화방 퇴장

즉, 이번 개편의 목표는 완전히 새로운 체계를 만드는 것이 아니라,
이미 존재하는 로컬 참조 구현들과 과거 PC통신 관례의 교집합으로
www-bbs를 수렴시키는 것이다.


3. 현재 계획서의 문제점 요약

기존 CMD_UPDATE_PLAN.txt는 방향은 맞지만, 실제 개발에 투입하기에는 아래 문제가 있다.

2026-03-23 최종 적용 상태

- 표준 검색 명령은 LT, LI로 고정했다.
- SW, SN, LN, SI 같은 구 검색 명령은 제거했다.
- LS, PF, US, PE 같은 숨은 호환 명령도 제거했다.
- runtime help, 사용자 가이드, 상태 핸들러, 스모크 테스트를 모두 같은 기준으로 맞췄다.
- 아래 본문에 남아 있는 "1차 호환" 표현은 검토 이력으로 보고, 현재 기준은 이 상태 블록과 10장 결론을 따른다.

3-1. 검색 명령어 기준이 최신 합의와 맞지 않는다.

기존 계획서는 SW, SI, SN 계열을 새 표준으로 잡았지만,
현재 구현과 최신 기준은 LT, LI만 남기는 쪽으로 정리됐다.
닉네임은 아이디와 같은 구조로 취급하므로 LN과 SN도 별도 명령으로 두지 않는다.
SI는 제거 대상으로 확정했다.

3-2. runtime help 생성기를 놓치고 있다.

legacy/txt/help.txt만 바꾸면 끝나는 구조가 아니다.
실제 /api/assets/help.txt는 www-bbs/src/server/createRequestHandler.js 안에서
동적으로 생성되고 있어서, 이 파일을 같이 수정하지 않으면 런타임 도움말은
계속 구 체계로 나온다.

3-3. P, M, L, LS의 역할 구분이 없다.

현재 계획서는 "이전"과 "목록"과 "첫 페이지"가 혼재되어 있다.
이걸 분리하지 않으면 구현 단계에서 문맥별 충돌이 난다.

권장 의미는 아래처럼 분리해야 한다.

- P / M : 바로 이전 문맥으로 복귀
- L     : 현재 목록의 첫 페이지 또는 전체 목록으로 복귀
- LS    : 제거

3-4. PE를 삭제만 하고 대체 경로를 정하지 않았다.

현재 코드에는 _editProfile() 기능이 존재하지만 기본 명령 체계에는 포함하지 않는다.
내 정보 수정은 터미널 명령이 아니라 API 경로로 안내하는 편이 맞다.
따라서 PE는 문서와 코드에서 모두 제거하는 쪽으로 정리한다.

3-5. 한글 오타 alias 계획이 너무 얕다.

현재 InputHandler.js는 한 글자짜리 alias만 처리한다.
하지만 실제로 필요한 것은 /ㅂ -> /q 같은 slash 명령과
두세 글자짜리 조합 alias까지 처리하는 정규화 레이어다.

3-6. old command를 어떤 범위까지 호환할지 정책이 없다.

DIR, LS, SW, SN, LN, PF, US, PE 같은 명령을 어디까지 유지할지 정책이 필요했지만,
최종적으로는 사용자 체계에서 모두 제거하는 쪽으로 정리했다.


4. 최종 목표 명령어 체계

4-1. 공통 원칙

1) 사용자 문서에는 "표준 명령어"만 노출한다.
2) 구 명령어는 사용자 체계와 코드 경로에서 제거한다.
3) 상태별 문맥 차이는 표준 명령만으로 해결한다.
4) 빈 Enter는 목록/본문/서비스 뷰에서 "다음 페이지"로 쓴다.
5) 채팅방 내부에서 빈 Enter는 메시지 전송에 사용하므로 예외로 둔다.
6) UP/DN은 일반 페이지 이동보다는 첨부 업/다운 또는 채팅 스크롤 용도로만 남긴다.

4-2. 전역 명령어 표준안

이전 화면 / 상위 메뉴
  현재 문서 표기: P 또는 LS
  최종 표준: P 또는 M
  1차 호환: 없음
  비고: 사용자 문서, 도움말, 프롬프트, 상태 핸들러 모두 P/M만 사용한다.

도움말
  현재 문서 표기: H
  최종 표준: C 또는 H
  1차 호환: H 유지
  비고: 안내 의미가 더 강한 C를 앞에 둔다. 프롬프트 라벨은 H 단독

직접 이동
  현재 문서 표기: GO
  최종 표준: GO [이름]
  1차 호환: 그대로
  비고: 하이텔/천리안/나우누리 공통 관찰과도 일치하므로 유지한다.

활동 사용자 보기
  현재 문서 표기: US
  최종 표준: USER
  1차 호환: 없음
  비고: 문서와 도움말, 코드 모두 USER만 사용한다.

회원 정보 보기
  현재 문서 표기: PF [아이디]
  최종 표준: WHO [아이디]
  1차 호환: 없음
  비고: 표준 노출과 실제 처리 모두 WHO로 통일한다.

프로필 편집
  현재 문서 표기: PE
  최종 표준: 문서 기본 명령어에서 제거
  1차 호환: 없음
  비고: 프로필 수정은 POST /api/members/profile API 경로로 안내한다.

시스템 정보
  현재 문서 표기: SYS
  최종 표준: SYS
  1차 호환: 그대로
  비고: 완전한 고전 명령은 아니지만 구현과 smoke test가 이미 가정하고 있으므로 유지한다.

메모함
  현재 문서 표기: XX
  최종 표준: XX
  1차 호환: 필요 시 MEMOS
  비고: 현재 코드와 문서가 모두 XX 기준이므로 기본 노출은 XX로 유지한다.

종료
  현재 문서 표기: X 또는 BYE
  최종 표준: X 또는 BYE
  1차 호환: 그대로
  비고: QUIT는 전역 종료 명령보다 대화방의 /QUIT 맥락에 묶는 편이 덜 혼란스럽다.

4-3. 게시판 목록 화면 표준안

글 읽기
  현재 문서 표기: [번호]
  최종 표준: [번호]
  1차 호환: 그대로

다음 페이지
  현재 문서 표기: N
  최종 표준: Enter 또는 F
  1차 호환: 
  비고: 문서 표준은 Enter/F로 노출한다. N은 다음 글

이전 페이지
  현재 문서 표기: B
  최종 표준: B
  1차 호환: 그대로

첫 페이지 / 목록 원복
  현재 문서 표기: DIR
  최종 표준: L
  1차 호환: 없음
  비고: L은 첫 페이지 + 검색 해제까지 담당하도록 맞췄다.

검색
  현재 문서 표기: LT, LI, LN, LC
  최종 표준: LT, LI
  1차 호환: 없음
  비고: LT는 제목+본문, LI는 작성자 검색으로 고정한다.
        현재 구조에서는 닉네임이 아이디와 같으므로 SI/LN을 별도 표준으로 두지 않는다.

글쓰기
  현재 문서 표기: W
  최종 표준: W
  1차 호환: 그대로

목록에서 수정 / 삭제
  현재 문서 표기: 문서에는 약하게 노출됨
  최종 표준: EDIT [번호], DD [번호]
  1차 호환: 그대로

이전 문맥 복귀
  현재 문서 표기: P 또는 LS
  최종 표준: P 또는 M
  1차 호환: 없음

4-4. 게시글 읽기 화면 표준안

다음 본문 페이지
  현재 문서 표기: N 또는 DN
  최종 표준: Enter
  1차 호환: F
  비고: 표준은 Enter만 앞세운다. F는 보조 호환 정도로만 남긴다.

이전 본문 페이지
  현재 문서 표기: B 또는 UP
  최종 표준: B
  1차 호환: 
  비고: UP을 일반 페이지 이동 의미에서 걷어내야 첨부 업로드와 충돌이 줄어든다.

다음 글 연속 읽기
  현재 문서 표기: ]
  최종 표준: A
  1차 호환: ]

이전 글 연속 읽기
  현재 문서 표기: [
  최종 표준: N
  1차 호환: [

이전 목록으로 복귀
  현재 문서 표기: P 또는 LS
  최종 표준: P 또는 M
  1차 호환: LS
  비고: P/M은 state stack을 사용해 "직전 목록 페이지와 검색 상태"를 복원해야 한다.

목록 첫 페이지로 이동
  현재 문서 표기: 별도 없음 또는 LS로 혼용
  최종 표준: L
  1차 호환: LS
  비고: L은 현재 게시판의 첫 페이지로 직접 간다.

답글 / 수정 / 삭제 / 추천 / 인쇄
  현재 문서 표기: RE, EDIT, DD, OK, PR
  최종 표준: RE, EDIT, DD, OK, PR
  1차 호환: EDIT -> EDIT
  비고: 문서에서 EDIT 풀네임을 빼고 ED로 통일한다.

4-6. 대화방 내부 표준안

메시지 전송
  현재 문서 표기: [문자열]
  최종 표준: [문자열] 입력 후 Enter
  1차 호환: 그대로

퇴장
  현재 문서 표기: LS
  최종 표준: /Q 또는 /QUIT
  1차 호환: LS

대화 스크롤
  현재 문서 표기: 없음 또는 암시적

  1차 호환: B / N
  비고: 채팅방 내부만큼은 일반 목록과 달리 Enter가 전송이므로 스크롤 명령을 분리한다.

향후 확장 후보

  /LIST           참여자 목록
  /Z              최근 대화 재표시
  비고: olddos, ezbbs 참조 기능이며 2차 범위로 두는 것이 현실적이다.

4-8. 메모함 표준안

메모 목록
  [번호] : 읽기

  DD [번호] : 삭제
  Enter 또는 F : 다음 페이지
  B : 이전 페이지

  B : 이전 페이지

  P 또는 M : 이전 문맥
  PR : 인쇄

4-9. 한글 오타 alias 표준안

현재 InputHandler.js는 단문자 alias만 처리한다.
최종 목표는 "입력 정규화 함수"를 따로 두는 것이다.

반드시 지원할 1차 alias

- ㅅ  -> t
- ㅊ  -> c
- ㅔ  -> p
- ㅡ  -> p
- ㅁ  -> a
- ㅜ  -> n
- ㅈ  -> w
- ㅣ  -> l

slash alias 1차 지원

- /ㅂ    -> /q
- /ㅂㅂ  -> /quit

legacy symbol alias 1차 지원

- ] -> a
- [ -> n

상태별 legacy alias 1차 지원

- board/service/chat directory 상태의 n -> f
- board/service/chat directory 상태의 dir -> l
- board/service/chat directory 상태의 ls -> p 또는 m
- board search의 lt -> sw
- board search의 li -> si
- board search의 ln -> sn
- article 상태의 dn -> enter(next page)로 해석하지 말고
  첨부 다운로드와 충돌하지 않도록 명확히 분리해야 한다.

핵심 원칙은 "alias 변환은 parse 이전에 하되, 상태 의존적으로 한다"이다.
InputHandler에서 일괄 처리하지 말고 BbsStateManager의 normalize 단계로 옮겨야 한다.

8. 검증 체크리스트

8-1. 전역

- C, H 둘 다 도움말이 열린다.
- USER가 활동 사용자 화면을 연다.
- WHO guest가 회원 정보 화면을 연다.
- GO notice, GO chat, GO weather가 동작한다.

8-2. 게시판 목록

- Enter가 다음 페이지로 이동한다.
- F도 다음 페이지로 이동한다.
- B가 이전 페이지로 이동한다.
- L이 첫 페이지이면서 검색을 해제한다.
- LT와 LI가 각각 제목/본문, 작성자 검색으로 반영된다.
- SW, SN, LN, SI는 더 이상 검색 명령으로 동작하지 않는다.

8-3. 게시글 읽기

- Enter가 다음 본문 페이지로 이동한다.
- B가 이전 본문 페이지로 이동한다.
- A가 다음 글, N이 이전 글로 이동한다.
- ]/[가 1차 호환으로 A/N에 매핑된다.
- P/M은 직전 목록 페이지와 검색 상태를 복원한다.
- L은 현재 게시판 첫 페이지로 간다.
- RE/ED/DD/OK/PR이 모두 동작한다.
- LA, NA, PA, UP, DN이 첨부 흐름과 충돌 없이 동작한다.

8-4. 대화방

- 목록에서 O가 방을 개설한다.
- 목록에서 Enter/F가 다음 페이지, B가 이전 페이지, L이 첫 페이지로 동작한다.
- 방 안에서 메시지 입력 후 Enter가 전송된다.
- /Q, /QUIT가 퇴장한다.
- LS가 더 이상 동작하지 않는지 확인한다.

8-5. 서비스 / 메모함

- 모든 목록형 화면에서 Enter/F, B, L, P/M이 일관되게 동작한다.
- 메모 상세에서 RE/W, DD, OK, PR이 동작한다.

8-6. 도움말

- /api/assets/help.txt 내용이 실제 명령어와 일치한다.
- USER_GUIDE_www-bbs.txt의 설명과 실제 동작이 일치한다.
- 상태바 하단 힌트 문구와 도움말이 서로 충돌하지 않는다.


9. 이번 개편에서 같이 고쳐야 하는 핵심 결정 사항

결정 1. 검색 명령은 LT/LI로 확정한다.
이유:
현재 기준은 LT/LI만 남기고,
SW, SN, LN, SI를 모두 제거하는 쪽으로 정리됐다.

결정 2. P/M과 L의 의미를 분리한다.
이유:
이 구분이 없으면 article -> board 복귀 경험이 계속 어색하다.

결정 3. LS는 문서와 코드에서 모두 제거한다.
이유:
LS는 Unix 느낌과 old web 습관이 섞인 명령이라 유지 가치가 낮다.

결정 4. runtime help 생성기까지 반드시 수정한다.
이유:
legacy/txt/help.txt만 고쳐서는 실제 사용자 화면이 바뀌지 않는다.

결정 5. PE는 터미널 명령에서 제거하고 API 경로로 분리한다.
이유:
계정정보 수정 경로는 필요하지만, 기본 명령 체계와는 분리하는 편이 맞다.


10. 최종 결론

www-bbs의 명령어 개편은 단순히 몇 개의 약어를 바꾸는 일이 아니다.
이번 정리는 문서, 런타임 도움말, 프롬프트, 상태별 핸들러, 스모크 테스트를
LT/LI, P/M, L, WHO, USER, /Q 중심의 단일 체계로 맞추는 작업이다.

따라서 이번 작업은 아래 순서로 가야 한다.

1) 표준 명령어를 LT/LI, P/M, L, Enter, A/N, O, /Q 중심으로 동결한다.
2) legacy alias는 남기지 않는다.
3) USER_GUIDE_www-bbs.txt와 /api/assets/help.txt, 상태 핸들러를 같은 체계로 유지한다.
4) 그 다음 BbsStateManager의 상태별 동작을 표준안에 맞게 정리한다.
5) 마지막으로 smoke test와 UI 힌트를 동기화한다.

이 순서를 지키면 "문서만 바뀌고 실제 명령은 안 바뀌는 문제"와
"코드는 바뀌었는데 도움말이 옛날 명령을 계속 보여주는 문제"를 같이 막을 수 있다.
