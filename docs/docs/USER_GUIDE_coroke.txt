================================================================================
  1. 프로젝트 개요
================================================================================

  01410.coroke.net 은 1990년대 PC통신(VT서비스) 시대의 사용자 경험을
  웹 브라우저에서 체험할 수 있는 서비스입니다.

  "파란 화면에 표시되는 글자만으로 사람들과 연결되는 경험"을
  역사의 뒤안길로 사라지지 않고 보존하기 위해 제작되었습니다.

  주요 기능:
  - 소셜 로그인 (Twitter OAuth1, Google OAuth2)
  - 게시판 (자유게시판, 창작연재, 친구찾아요, 공지사항)
  - 게시글 읽기 / 쓰기 (페이징, 조회수, 이전/다음 글)
  - 도움말, 소개 페이지 등 정적 텍스트 페이지
  - 접속 시간 표시 및 다이얼업 모뎀 효과음
  - 모바일 반응형 대응

  기술 스택:
  - 백엔드: Kotlin / Spring Boot 2.7.4 / Java 17
  - 프론트엔드: HTML + CSS + JavaScript (번들러 없음)
  - 데이터베이스: MariaDB
  - 인증: Spring Security + OAuth2 (Google) + OAuth1 (Twitter)
  - 세션: Spring Session JDBC
  - 배포: Docker + Nginx 리버스 프록시


================================================================================
  2. 사전 준비 사항
================================================================================

  2-1. 필수 소프트웨어

    - Java Development Kit (JDK) 17 이상
      확인 방법: java --version
      권장: OpenJDK 18 (Dockerfile에서 openjdk:18.0.2.1-slim 사용)

    - Gradle (프로젝트에 gradlew 래퍼 포함되어 있으므로 별도 설치 불필요)
      Windows: gradlew.bat
      Linux/macOS: ./gradlew

  2-2. 필수 외부 서비스

    - MariaDB 데이터베이스 서버
      설치 및 실행 후 다음 정보가 필요합니다:
        - DB 호스트 주소 (예: localhost)
        - DB 사용자 이름
        - DB 비밀번호
        - DB 데이터베이스 이름
      테이블은 JPA가 자동으로 생성합니다.
      (spring.jpa.hibernate.ddl-auto=update 설정)

    - Twitter 개발자 계정 (https://developer.twitter.com)
      Twitter 로그인 기능을 사용하려면 Twitter App을 생성하고
      OAuth 1.0a Consumer Key와 Consumer Secret을 발급받아야 합니다.

    - Google Cloud Console (https://console.cloud.google.com)
      Google 로그인 기능을 사용하려면 OAuth 2.0 클라이언트 ID를
      생성하고 Client ID와 Client Secret을 발급받아야 합니다.
      승인된 리디렉션 URI에 다음을 추가해야 합니다:
        https://[도메인]/{action}/oauth2/code/google

  2-3. 선택 사항

    - Docker (컨테이너 배포 시 필요)
      확인 방법: docker --version

    - Nginx (정적 파일 캐시 및 리버스 프록시용)


================================================================================
  3. 설치 및 실행
================================================================================

  3-1. 소스 코드 다운로드

    git clone [저장소 URL]
    cd 01410.coroke.net-main

  3-2. 환경 변수 설정

    프로젝트 루트의 env.env 파일을 편집합니다.
    (4장 "환경 변수" 참조)

  3-3. 빌드 (JAR 컴파일)

    Windows:
      gradlew.bat bootJar

    Linux/macOS:
      ./gradlew bootJar

    빌드가 성공하면 다음 경로에 JAR 파일이 생성됩니다:
      build/libs/terminal-1.0.0.jar

  3-4. 서버 실행

    환경 변수를 로드한 뒤 JAR 파일을 실행합니다:

    Windows:
      set /p DB_HOST=<env.env (또는 직접 환경변수 설정)
      java -jar build/libs/terminal-1.0.0.jar

    Linux/macOS (환경변수 파일을 소스하여 실행):
      export $(cat env.env | xargs)
      java -jar build/libs/terminal-1.0.0.jar

    또는 Gradle로 직접 실행:
      gradlew.bat bootRun  (Windows)
      ./gradlew bootRun    (Linux/macOS)

    서버가 시작되면 기본 포트 8080에서 동작합니다.

  3-5. 브라우저에서 접속

    웹 브라우저를 열고 다음 주소로 접속합니다:

    http://localhost:8080/

    파란 배경에 환영 화면이 나타나면 성공입니다.
    Enter 키를 누르면 다이얼업 모뎀 효과음이 재생되며
    메인 메뉴로 진입합니다. (효과음을 끄려면 S 키 입력 후 Enter)

  3-6. Docker로 실행

    1단계: JAR 빌드
      gradlew.bat bootJar

    2단계: Docker 이미지 빌드
      docker build -t terminal .

    3단계: 컨테이너 실행
      docker run -d -p 8080:8080 \
        -e DB_HOST=호스트 \
        -e DB_USER=사용자 \
        -e DB_PASSWORD=비밀번호 \
        -e DB_NAME=데이터베이스 \
        -e TWITTER_CLIENT_ID=트위터키 \
        -e TWITTER_CLIENT_SECRET=트위터시크릿 \
        -e GOOGLE_CLIENT_ID=구글키 \
        -e GOOGLE_CLIENT_SECRET=구글시크릿 \
        -v /path/to/app.jar:/app/app.jar \
        terminal

    Docker 컨테이너는 8080 포트를 노출합니다.
    JVM 메모리: 최소 64MB, 최대 384MB로 제한됩니다.


================================================================================
  4. 환경 변수 (env.env) 설정
================================================================================

  프로젝트 루트의 env.env 파일에 다음 값들을 설정합니다.
  Spring Boot가 application.properties에서 ${변수명} 형태로 참조합니다.

  --------------------------------------------------------------------------
  데이터베이스 설정
  --------------------------------------------------------------------------

  DB_HOST=
    MariaDB 서버 호스트 주소입니다.
    예: localhost  또는  db.example.com

  DB_USER=
    MariaDB 사용자 이름입니다.
    예: root

  DB_PASSWORD=
    MariaDB 비밀번호입니다.
    예: my-secret-password

  DB_NAME=
    사용할 데이터베이스 이름입니다.
    예: terminal
    미리 MariaDB에서 해당 데이터베이스를 생성해 두어야 합니다.
      CREATE DATABASE terminal CHARACTER SET utf8mb4;

  --------------------------------------------------------------------------
  Twitter OAuth 설정
  --------------------------------------------------------------------------

  TWITTER_CLIENT_ID=
    Twitter Developer Portal에서 발급받은 API Key (Consumer Key)입니다.

  TWITTER_CLIENT_SECRET=
    Twitter Developer Portal에서 발급받은 API Secret (Consumer Secret)입니다.

    Twitter 로그인 흐름:
      1. 사용자가 L > 1 을 선택
      2. /login/oauth1/twitter 로 리다이렉트
      3. Twitter 인증 페이지로 이동
      4. 인증 완료 후 /login/oauth1/twitter/callback 으로 콜백
      5. 세션에 사용자 정보 저장 후 메인 페이지로 리다이렉트

  --------------------------------------------------------------------------
  Google OAuth 설정
  --------------------------------------------------------------------------

  GOOGLE_CLIENT_ID=
    Google Cloud Console에서 발급받은 OAuth 2.0 클라이언트 ID입니다.

  GOOGLE_CLIENT_SECRET=
    Google Cloud Console에서 발급받은 OAuth 2.0 클라이언트 시크릿입니다.

    Google 로그인 흐름:
      1. 사용자가 L > 2 를 선택
      2. /login/oauth2/authorization/google 로 리다이렉트
      3. Google 인증 페이지로 이동
      4. 인증 완료 후 /login/oauth2/callback 으로 콜백
      5. 세션에 사용자 정보 저장 후 메인 페이지로 리다이렉트

    주의: Google Cloud Console에서 승인된 리디렉션 URI에
    https://[도메인]/{action}/oauth2/code/google 을 반드시 등록해야 합니다.


================================================================================
  5. 애플리케이션 설정 (application.properties)
================================================================================

  src/main/resources/application.properties 파일의 주요 설정 항목입니다.

  --------------------------------------------------------------------------
  JPA / 데이터베이스
  --------------------------------------------------------------------------

  spring.jpa.hibernate.ddl-auto=update
    서버 시작 시 엔티티와 테이블 스키마를 자동으로 동기화합니다.
    테이블이 없으면 자동 생성, 컬럼이 추가되면 자동 반영합니다.
    운영 환경에서는 validate 또는 none으로 변경하는 것을 권장합니다.

  spring.jpa.generate-ddl=true
    DDL 자동 생성을 활성화합니다.

  spring.jpa.show-sql=false
    콘솔에 SQL 쿼리를 출력할지 여부입니다. 디버깅 시 true로 변경합니다.

  spring.datasource.driverClassName=org.mariadb.jdbc.Driver
    MariaDB JDBC 드라이버를 사용합니다.

  spring.datasource.url=jdbc:mariadb://${DB_HOST}:3306/${DB_NAME}?...
    MariaDB 연결 URL입니다. 기본 포트 3306을 사용합니다.

  --------------------------------------------------------------------------
  세션
  --------------------------------------------------------------------------

  spring.session.store-type=jdbc
    세션을 JDBC(데이터베이스)에 저장합니다.
    SPRING_SESSION 테이블이 자동으로 생성됩니다.

  spring.session.timeout=600
    세션 타임아웃 시간 (초)입니다. 기본 10분(600초)입니다.

  --------------------------------------------------------------------------
  프록시
  --------------------------------------------------------------------------

  server.tomcat.protocol-header=x-forwarded-proto
  server.tomcat.remote-ip-header=x-forwarded-for
  server.use-forward-headers=true
    Nginx 등 리버스 프록시 뒤에서 동작할 때 필요한 설정입니다.
    프록시가 전달하는 원본 IP와 프로토콜(HTTPS)을 올바르게 인식하게 합니다.

================================================================================
  7. 터미널 사용법 (일반 사용자)
================================================================================

  브라우저에서 접속하면 파란 배경의 환영 화면이 나타납니다.
  화면 하단에 "선택>" 프롬프트가 표시되며,
  명령어를 입력하고 Enter를 누르면 실행됩니다.

  화면 맨 아래에는 상태 바가 표시됩니다:
  - 왼쪽: "연결 0:00" (접속 시간, 매초 갱신)
  - 가운데: "1-9600-N-8-1" (PC통신 시대의 모뎀 설정 표시, 장식용)
  - 오른쪽: 현재 시각 (HH:MM:SS)

  --------------------------------------------------------------------------
  7-1. 기본 명령어
  --------------------------------------------------------------------------

  전체 화면 어디에서든 사용할 수 있는 명령어입니다.
  대소문자를 구분하지 않습니다. (예: T, t 모두 사용 가능)
  한글 입력 상태에서도 동작합니다. (예: ㅅ = T, ㅊ = C)

  T (또는 ㅅ)     초기 메뉴(TOP)로 돌아갑니다.
                   어디에서든 T를 입력하면 처음으로 돌아갑니다.

  P 또는 M         이전 화면(상위 메뉴)으로 돌아갑니다.
  (또는 ㅔ 또는 ㅡ)  게시글을 읽고 있을 때는 게시글 목록으로 돌아갑니다.

  C (또는 ㅊ)     도움말(명령어 안내)을 표시합니다.
                   help.txt의 내용이 표시됩니다.

  L (또는 ㅣ)     로그인 화면을 엽니다.
                   (이미 로그인된 상태에서는 메인 메뉴에 표시되지 않음)

  X (또는 ㅌ)     종료합니다.
                   로그아웃 후 환영 화면으로 돌아갑니다.
                   세션이 종료되고 SESSION 쿠키가 삭제됩니다.

  GO [이름]       특정 페이지나 게시판으로 바로 이동합니다.
                   예: GO plaza     -> 자유게시판으로 바로 이동
                   예: GO creative  -> 창작연재로 바로 이동
                   예: GO friend    -> 친구찾아요로 바로 이동
                   예: GO notice    -> 공지사항으로 바로 이동
                   예: GO about     -> 서비스 소개로 이동
                   예: GO help      -> 도움말로 이동
                   GO 명령은 메인 메뉴(TOP)에서만 사용 가능합니다.

  SET NICKNAME    닉네임(이용자명)을 변경합니다.
                   (최초 로그인 시 자동으로 닉네임 설정 화면이 나타남)

  --------------------------------------------------------------------------
  7-2. 메뉴 구조 및 페이지 이동
  --------------------------------------------------------------------------

  메인 메뉴(TOP)에서 번호를 입력하면 해당 하위 메뉴로 이동합니다.

  routes.json에 정의된 기본 메뉴 구조:

  TOP (메인 메뉴)
  |-- 1: plaza     자유게시판 (게시판)
  |-- 2: creative  창작연재 (게시판)
  |-- 3: friend    친구찾아요 (게시판)
  |-- 98: about    서비스 소개 (텍스트 페이지)
  |-- 99: notice   공지사항 (게시판, 관리자만 글쓰기 가능)

  기타 접근 가능한 페이지:
  - help           도움말 (텍스트 페이지, C 명령으로 접근)
  - welcome        환영 화면 (첫 화면)
  - error          에러 화면 (잘못된 URL 접근 시)

  페이지 유형:
  - "page" 타입: txt 디렉토리의 텍스트 파일을 불러와 표시합니다.
  - "board" 타입: API를 통해 게시글 목록을 불러와 표시합니다.

  --------------------------------------------------------------------------
  7-3. 게시판 사용법
  --------------------------------------------------------------------------

  메인 메뉴에서 번호를 입력하거나 GO [게시판이름]으로 게시판에 진입합니다.

  게시판에 들어가면 게시글 목록이 표시됩니다.
  각 게시글은 번호, 이용자명, 날짜, 읽음수(조회수), 제목이 표시됩니다.

  게시판 목록 화면의 명령어:

  [번호]         해당 번호의 게시글을 읽습니다.
                 예: 3  -> 3번 게시글 읽기

  Enter 또는 F   다음 페이지로 이동합니다.
  (또는 ㄹ)      마지막 페이지(EOF)에 도달하면 더 이상 이동하지 않습니다.

  B (또는 ㅠ)    이전 페이지로 이동합니다.
                 첫 페이지에서는 동작하지 않습니다.

  W (또는 ㅈ)    새 게시글을 작성합니다. (로그인 필요)
                 로그인하지 않은 상태에서 W를 입력하면
                 자동으로 로그인 화면이 나타납니다.
                 공지사항(notice)은 관리자만 글쓰기가 가능합니다.

  P 또는 M       이전 화면(메인 메뉴 등)으로 돌아갑니다.

  화면 하단에 현재 페이지/전체 페이지 수가 표시됩니다.
  각 페이지에는 12개의 게시글이 표시됩니다.

  --------------------------------------------------------------------------
  7-4. 게시글 읽기/쓰기
  --------------------------------------------------------------------------

  게시글 읽기:

  게시글을 선택하면 다음 정보가 표시됩니다:
  - 제목
  - 올린이 (작성자 닉네임)
  - 작성 날짜 (YY-MM-DD HH:mm, 한국 시간 기준)
  - 분량 (총 페이지 수)
  - 읽음 수 (조회수)
  - 구분선 아래에 본문 내용

  게시글 읽기 화면의 명령어:

  Enter 또는 F   다음 페이지로 스크롤합니다.
  (또는 ㄹ)      한 페이지에 10줄씩 표시됩니다.
                 마지막 페이지에 |EOF| 표시가 나타나면 끝입니다.

  B (또는 ㅠ)    이전 페이지로 스크롤합니다.

  A (또는 ㅁ)    다음 게시글(최신 글 방향)로 이동합니다.
                 (forward 방향: aliasId가 큰 글)

  N (또는 ㅜ)    이전 게시글(오래된 글 방향)로 이동합니다.
                 (backward 방향: aliasId가 작은 글)

  P 또는 M       게시판 목록으로 돌아갑니다.

  조회수 처리:
  - 같은 게시글을 처음 읽을 때만 조회수가 증가합니다.
  - 세션 단위로 중복 카운트를 방지합니다.
  - 클라이언트 측에서도 localStorage를 사용하여
    이미 읽은 글의 조회수 API 호출을 건너뜁니다.

  게시글 쓰기:

  1단계: W 입력 (로그인 필요)
  2단계: 제목 입력
    "제목을 입력하세요. 한글 30자 영문 60자 이내" 안내가 나타납니다.
    제목을 입력하고 Enter를 누릅니다.
    빈 제목을 입력하면 작성이 취소됩니다.

  3단계: 본문 입력
    "글을 작성한 후 마지막줄 첫칸에 마침표(.)를 찍고 엔터를 치면 끝납니다"
    안내가 표시됩니다.
    텍스트 영역이 나타나며 자유롭게 본문을 입력합니다.
    작성이 끝나면 새 줄의 첫 칸에 마침표(.)를 입력하고 Enter를 눌러 종료합니다.

  4단계: 등록 확인
    "이 글을 등록하시겠습니까? (Y/n)" 확인이 표시됩니다.
    Y 또는 Enter를 누르면 게시글이 등록됩니다.
    N을 누르면 작성이 취소됩니다.

  --------------------------------------------------------------------------
  7-5. 로그인 (소셜 인증)
  --------------------------------------------------------------------------

  L 명령을 입력하면 로그인 화면이 나타납니다.

  "로그인 할 계정을 선택해주세요"
    1. Twitter
    2. Google
    0. 취소

  1을 선택하면 Twitter 인증 페이지로 이동합니다.
  2를 선택하면 Google 인증 페이지로 이동합니다.
  0 또는 N을 선택하면 로그인을 취소합니다.

  인증이 완료되면 자동으로 BBS 메인 페이지로 돌아옵니다.
  로그인 전에 보고 있던 URL은 localStorage에 저장되어
  로그인 후 해당 페이지로 복귀합니다.

  로그인하지 않은 상태에서 글쓰기(W)를 시도하면
  "로그인이 필요합니다." 안내와 함께 로그인 화면이 자동으로 나타납니다.

  --------------------------------------------------------------------------
  7-6. 닉네임(이용자명) 설정
  --------------------------------------------------------------------------

  최초 로그인 시 닉네임이 비어있으면 자동으로 닉네임 설정 화면이 나타납니다.

  "이용자명을 지정해주세요.
   이용자명은 게시판 등에 표시되며 수정이 불가합니다.
   한글 4자 영문 8자 이내"

  닉네임 규칙:
  - 한글, 영문, 숫자만 허용됩니다. (특수문자 불가)
  - 바이트 기준 최소 4바이트 이상 (한글 2자 이상, 영문 4자 이상)
  - 바이트 기준 최대 8바이트 (한글 4자, 영문 8자)
  - 이미 사용 중인 닉네임은 사용할 수 없습니다.
  - 한 번 설정하면 변경이 불가합니다.
    (SET NICKNAME 명령으로 변경 시도는 가능하나, 기존 닉네임이 있으면
     UserRepository에서 중복 체크 후 거부됩니다.)

  사용 불가한 닉네임을 입력하면
  "사용할 수 없는 이용자명입니다. 다른 이용자명을 지정해주세요."
  안내가 나타납니다.


================================================================================
  8. 관리자 기능
================================================================================

  사용자 역할은 두 가지입니다:
  - ROLE_USER   일반 사용자
  - ROLE_ADMIN  관리자

  관리자 전용 기능:

  8-1. 공지사항 글쓰기
    routes.json에서 notice 게시판에
    "write_permissions": "admin" 이 설정되어 있습니다.
    관리자(ROLE_ADMIN)만 공지사항에 글을 쓸 수 있습니다.
    일반 사용자가 공지사항에서 W를 입력하면
    "글쓰기 권한이 없습니다." 메시지가 표시됩니다.

  8-2. 관리자 지정 방법
    데이터베이스의 user 테이블에서 해당 사용자의
    role 컬럼 값을 'ROLE_ADMIN'으로 직접 변경합니다.
    SQL 예시:
      UPDATE user SET role = 'ROLE_ADMIN' WHERE username = '대상사용자';


================================================================================
  9. URL 라우팅
================================================================================

  이 프로젝트는 SPA 방식으로 동작하며,
  URL 경로를 통해 특정 화면에 직접 접근할 수 있습니다.

  URL 형식:

  /                              환영 화면 (welcome)
  /top                           메인 메뉴
  /plaza                         자유게시판 목록
  /plaza/[글번호]                자유게시판 특정 게시글
  /creative                      창작연재 목록
  /creative/[글번호]             창작연재 특정 게시글
  /friend                        친구찾아요 목록
  /friend/[글번호]               친구찾아요 특정 게시글
  /notice                        공지사항 목록
  /notice/[글번호]               공지사항 특정 게시글
  /about                         서비스 소개
  /help                          도움말

  서버 측 HomeController가 /[영문소문자]/ 패턴의 URL을
  routes.json과 대조하여 유효한 경로이면 index.html을 반환합니다.
  클라이언트 측 index.js가 URL을 파싱하여 해당 화면을 로드합니다.

  History API:
  - pushState로 URL을 변경합니다.
  - 브라우저의 뒤로가기/앞으로가기는 지원되지 않습니다.
    (popstate 이벤트 리스너가 없음)
  - 새로고침(F5)은 정상 동작합니다.
    (서버가 해당 경로에 대해 index.html을 반환하고,
     클라이언트가 URL을 파싱하여 해당 화면을 복원합니다.)

 10. 폰트 및 화면 구성
================================================================================

  10-1. 화면 규격

  데스크톱:
  - 전체 캔버스: 657px
  - 콘텐츠 영역: 640px x 465px
  - 상태 바: 18px 높이
  - 배경색: #070080 (진한 파란색)
  - 글자색: #FFFFFF (흰색)

  모바일 (640px 이하):
  - 전체: 400px x 312px
  - 콘텐츠: 400px x 300px
  - 상태 바: 12px 높이
  - 폰트 크기: 10px (데스크톱 16px의 축소)
  - 고정 위치(fixed) 레이아웃으로 스크롤 방지

  10-2. 폰트 전략

  기본 폰트 스택:
    font-family: DungGeunMo, Sam3KRFont, Fixedsys;

  DungGeunMo (둥근모)
    - CDN: projectnoonnu DungGeunMo.woff
    - 기본 텍스트에 사용됩니다.
    - 한글과 영문 모두 이 폰트로 표시됩니다.

  Sam3KRFont (삼국지 폰트)
    - CDN: projectnoonnu Sam3KRFont.woff
    - 선 기호(─│┌┐┘└ 등) 전용으로 사용됩니다.
    - CSS에서 i 태그에 별도로 font-family: Sam3KRFont 적용
    - transform: scaleY(1.5)로 세로 비율을 1.5배 확대하여
      선 기호가 줄 높이에 맞도록 조정합니다.

  Fixedsys
    - 시스템 폴백 폰트 (Windows 전용)

  10-3. 선 기호 처리

  index.js에서 다음 선 기호들을 자동으로 <i> 태그로 감쌉니다:
    ─ │ ┌ ┐ ┘ └ ├ ┬ ┤ ┴ ┼ ━ ┃ ┏ ┓ ┛ ┗ ┣ ┳ ┫ ┻ ╋

  이 <i> 태그에는 별도의 CSS가 적용되어:
  - Sam3KRFont 폰트 사용
  - 기울임체(italic) 해제 (font-style: normal)
  - 세로 비율 1.5배 확대 (transform: scaleY(1.5))

  10-4. 제목 표시줄

  게시판이나 정적 페이지에 진입하면 상단에 제목 표시줄이 나타납니다:
  - 1줄: "coroke" (반전 표시) + 구분선
  - 2줄: 현재 위치(게시판 이름) + 제목(중앙 정렬) + 페이지 정보
  - 3줄: 전체 구분선

  10-5. 하단 명령어 안내

  화면 하단에 현재 사용 가능한 명령어가 자동으로 표시됩니다:
  - 명령어안내(C)
  - 초기메뉴(T) 또는 로그인(L)
  - 글쓰기(W) 다음(Enter,F) 이전(B) (게시판일 때)
  - 직접이동(GO) (메인 메뉴일 때)
  - 글이동(A,N) 목록(P,M) (게시글 읽기 시)
  - 상위(P,M) 종료(X)

  10-6. 다이얼업 모뎀 효과음

  환영 화면(welcome)에서 Enter를 누르면
  dialup.mp3 파일이 재생됩니다.
  S 키를 입력 후 Enter를 누르면 효과음 없이 진입합니다.

 11. 배포 (Docker / Nginx)
================================================================================

  11-1. Docker 배포

  Dockerfile 설정:
  - 베이스 이미지: openjdk:18.0.2.1-slim
  - 포트: 8080
  - JVM 옵션:
    -XX:+UnlockExperimentalVMOptions
    -XX:+UseContainerSupport
    -Djava.security.egd=file:/dev/./urandom
    -Xms64m (최소 힙: 64MB)
    -Xmx384m (최대 힙: 384MB)
  - JAR 경로: /app/app.jar

  빌드 및 실행:
    gradlew bootJar
    docker build -t terminal .
    docker run -d -p 8080:8080 \
      -e DB_HOST=... \
      -e DB_USER=... \
      -e DB_PASSWORD=... \
      -e DB_NAME=... \
      -e TWITTER_CLIENT_ID=... \
      -e TWITTER_CLIENT_SECRET=... \
      -e GOOGLE_CLIENT_ID=... \
      -e GOOGLE_CLIENT_SECRET=... \
      -v /path/to/terminal-1.0.0.jar:/app/app.jar \
      terminal

  11-2. Nginx 리버스 프록시

  nginx-terminal.conf 파일이 제공됩니다.
  이 설정을 Nginx에 적용하면 정적 파일 성능이 향상됩니다.

  주요 설정:
  - upstream terminal: 백엔드 서버 (terminal:8080)
    - ip_hash: 세션 유지를 위한 IP 해시 분산
    - keepalive 10: 연결 풀 유지

  - "/" 경로: static 디렉토리에서 index.html 제공
  - .css, .js, .mp3, .txt, .json, .woff, .jpg, .png, .ico 파일:
    static 디렉토리에서 직접 제공 (expires 1d, 접근 로그 끔)
  - 그 외 경로: 백엔드로 프록시

  정적 파일 경로 설정:
    Nginx의 root 디렉토리를 /var/www/terminal/static/ 으로 설정하고
    src/main/resources/static/ 디렉토리의 파일들을 복사합니다.

  권장사항 (README 발췌):
    src/main/resources/static 은 nginx 등에서 바로 제공토록 설정하는 것을
    권장합니다. nginx-terminal.conf 설정파일을 참조하세요.


================================================================================
 12. 데이터베이스 스키마
================================================================================

  JPA가 자동으로 테이블을 생성/갱신합니다.
  (spring.jpa.hibernate.ddl-auto=update)

  12-1. feed 테이블 (게시글)

  컬럼명         타입              설명
  -------------------------------------------------------
  id             BIGINT (PK, AI)  게시글 고유 ID (자동 증가)
  board_id       VARCHAR          게시판 식별자 (예: plaza, notice)
  alias_id       INT              게시판 내 글 번호 (게시판별 1부터 증가)
  created_user_id BIGINT (FK)     작성자 User ID (user 테이블 참조)
  name           VARCHAR          작성자 닉네임 (작성 시점의 닉네임 복사)
  title          VARCHAR          게시글 제목
  text           TEXT             게시글 본문
  created_ip     VARCHAR          작성자 IP 주소
  created_agent  VARCHAR          작성자 User-Agent
  hit            INT              조회수 (기본값: 0)
  created_at     DATETIME         작성 일시 (자동 설정)
  updated_at     DATETIME         수정 일시 (자동 설정)

  12-2. user 테이블 (사용자)

  컬럼명         타입              설명
  -------------------------------------------------------
  id             BIGINT (PK, AI)  사용자 고유 ID (자동 증가)
  origin         VARCHAR          인증 출처 (twitter, google)
  uid            VARCHAR          외부 서비스의 고유 ID
  username       VARCHAR          사용자명 (이메일 앞부분 또는 트위터 ID)
  nickname       VARCHAR(NULL)    닉네임 (이용자명, 게시글에 표시)
  name           VARCHAR          소셜 계정의 실명
  email          VARCHAR          이메일 주소
  picture        VARCHAR          프로필 이미지 URL
  role           VARCHAR (ENUM)   역할 (ROLE_USER, ROLE_ADMIN)

  12-3. SPRING_SESSION 테이블 (세션)

  Spring Session JDBC가 자동으로 생성합니다.
  - SPRING_SESSION: 세션 데이터
  - SPRING_SESSION_ATTRIBUTES: 세션 속성 (user JSON 등)
  세션 타임아웃: 600초 (10분)

 13. API 엔드포인트 목록
================================================================================

  서버가 제공하는 REST API 목록입니다.

  --------------------------------------------------------------------------
  게시판 (FeedController)
  --------------------------------------------------------------------------

  GET  /api/board/[게시판ID]/[페이지번호]
    게시판의 게시글 목록을 반환합니다.
    페이지당 12개의 게시글이 표시됩니다.
    응답 형식: 일반 텍스트 (터미널 렌더링용)
    응답에 |[PAGE:현재/전체]| 태그와 |EOF| 태그가 포함됩니다.

  GET  /api/board/[게시판ID]/[글번호]/[페이지번호]
    특정 게시글의 내용을 반환합니다.
    페이지당 10줄씩 표시됩니다.
    응답 형식: 일반 텍스트
    응답에 |EOF| 태그가 포함됩니다 (마지막 페이지일 때).

  GET  /api/board/[게시판ID]/[글번호]/hit
    게시글 조회수를 1 증가시킵니다.
    세션 단위로 같은 글에 대한 중복 카운트를 방지합니다.
    응답: "ok"

  GET  /api/board/[게시판ID]/[글번호]/forward
    현재 글의 다음 글(aliasId가 더 큰 글)로 리다이렉트합니다.
    다음 글이 없으면 응답 없음.

  GET  /api/board/[게시판ID]/[글번호]/backward
    현재 글의 이전 글(aliasId가 더 작은 글)로 리다이렉트합니다.
    이전 글이 없으면 응답 없음.

  POST /api/board/[게시판ID]/new
    새 게시글을 작성합니다. (로그인 필요)
    요청 Body (JSON):
      { "title": "제목", "text": "본문" }
    aliasId는 해당 게시판의 마지막 번호 + 1로 자동 설정됩니다.
    title과 text에서 < 문자는 &lt;로 이스케이프됩니다.
    응답: "ok" (성공 시)

  --------------------------------------------------------------------------
  인증 (AuthController / TwitterController)
  --------------------------------------------------------------------------

  GET  /login
    OAuth2 로그인 시작 (메인 페이지로 리다이렉트)

  GET  /login/oauth2/callback
    OAuth2 (Google) 로그인 콜백
    세션에 사용자 정보를 JSON으로 저장합니다.
    메인 페이지로 리다이렉트합니다.

  GET  /login/oauth1/twitter
    Twitter OAuth1 인증 시작
    Twitter 인증 페이지로 리다이렉트합니다.

  GET  /login/oauth1/twitter/callback
    Twitter OAuth1 인증 콜백
    oauth_token, oauth_verifier 파라미터를 받아 처리합니다.
    세션에 사용자 정보를 저장합니다.

  GET/POST  /logout
    로그아웃 처리
    SESSION 쿠키를 삭제하고 세션을 무효화합니다.
    응답: "ok"

  --------------------------------------------------------------------------
  사용자 (UserController)
  --------------------------------------------------------------------------

  GET  /get_user
    현재 로그인한 사용자 정보를 반환합니다.
    응답 (JSON):
      { "username": "...", "nickname": "...",
        "name": "...", "picture": "...", "role": "ROLE_USER" }
    로그인하지 않은 경우 빈 응답 또는 null

  POST /api/user/nickname
    닉네임을 설정합니다. (로그인 필요)
    요청 Body (JSON):
      { "nickname": "새닉네임" }
    닉네임 규칙:
      - 한글/영문/숫자만 (정규식: ^[ㄱ-ㅎ가-힣a-zA-Z0-9]+$)
      - 바이트 기준 4바이트 이상
      - 바이트 기준 8바이트로 자동 절삭
      - 중복 불가
    응답: "ok" (성공) 또는 "Fail" (실패)

  --------------------------------------------------------------------------
  정적 파일
  --------------------------------------------------------------------------

  GET  /txt/[파일명].txt
    정적 텍스트 파일을 반환합니다.
    예: /txt/welcome.txt, /txt/top.txt, /txt/help.txt

  GET  /routes.json
    메뉴 구조 정의 파일을 반환합니다.

  GET  /index.css, /index.js, /dialup.mp3, /favicon.ico 등
    정적 자원 파일을 반환합니다.

 14. 문제 해결 (트러블슈팅)
================================================================================

  14-1. 서버가 시작되지 않는 경우

    원인: 환경 변수가 설정되지 않은 경우
    해결: env.env 파일의 모든 값이 채워져 있는지 확인하세요.
          환경 변수가 JVM에 전달되고 있는지 확인하세요.
          Gradle bootRun은 자동으로 환경 변수를 로드하지 않습니다.

    원인: MariaDB에 연결할 수 없는 경우
    해결: DB_HOST가 올바른지 확인하세요.
          MariaDB 서버가 실행 중인지 확인하세요.
          DB_NAME에 해당하는 데이터베이스가 생성되어 있는지 확인하세요.
          MariaDB 포트(3306)가 방화벽에서 열려 있는지 확인하세요.

    원인: JDK 버전이 맞지 않는 경우
    해결: java --version 으로 JDK 17 이상인지 확인하세요.

  14-2. 화면이 표시되지 않는 경우

    원인: 정적 파일이 제공되지 않는 경우
    해결: src/main/resources/static/ 디렉토리에
          index.html, index.css, index.js 파일이 존재하는지 확인하세요.

    원인: Nginx 설정이 잘못된 경우
    해결: Nginx를 사용한다면 static 파일 경로가 올바른지 확인하세요.
          /var/www/terminal/static/ 에 파일이 복사되었는지 확인하세요.

  14-3. 폰트가 깨지거나 정렬이 어긋나는 경우

    원인: CDN에서 웹폰트를 불러오지 못하는 경우
    해결: 인터넷 연결을 확인하세요.
          브라우저 개발자 도구(F12) > Network 탭에서
          DungGeunMo.woff, Sam3KRFont.woff 파일 응답을 확인하세요.

    원인: i 태그의 scaleY(1.5) 변환이 적용되지 않는 경우
    해결: index.css 파일에서 i 태그의 스타일이 올바른지 확인하세요.

  14-4. 로그인이 되지 않는 경우

    원인: OAuth 키가 설정되지 않은 경우
    해결: env.env의 TWITTER_CLIENT_ID, TWITTER_CLIENT_SECRET,
          GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET이 올바른지 확인하세요.

    원인: 리디렉션 URI가 올바르지 않은 경우
    해결:
      Google: Cloud Console에서 승인된 리디렉션 URI에
              https://[도메인]/{action}/oauth2/code/google 이 등록되어 있는지 확인하세요.
      Twitter: Developer Portal에서 Callback URL에
               https://[도메인]/login/oauth1/twitter/callback 이 등록되어 있는지 확인하세요.

    원인: HTTPS가 아닌 HTTP에서 접근하는 경우
    해결: application.properties의 redirect-uri가 https://로 시작합니다.
          로컬 개발 시에는 이 URL을 http://localhost:8080/... 으로 변경하거나
          리버스 프록시를 통해 HTTPS를 제공해야 합니다.

  14-5. 닉네임 설정이 실패하는 경우

    원인: 닉네임이 규칙에 맞지 않는 경우
    해결: 닉네임은 한글/영문/숫자만 가능합니다.
          바이트 기준 4바이트 이상이어야 합니다 (한글 2자, 영문 4자).
          이미 다른 사용자가 사용 중인 닉네임은 불가합니다.

  14-6. 게시글 작성이 실패하는 경우

    원인: 로그인하지 않은 상태
    해결: 글쓰기 전에 L 명령으로 로그인하세요.

    원인: 공지사항에 일반 사용자가 글쓰기를 시도한 경우
    해결: 공지사항은 ROLE_ADMIN만 글쓰기가 가능합니다.
          관리자 권한이 필요하면 DB에서 role 값을 변경하세요.

  14-7. Docker 컨테이너가 시작되지 않는 경우

    원인: JAR 파일이 마운트되지 않은 경우
    해결: docker run 시 -v 옵션으로 JAR 파일을 /app/app.jar에
          마운트했는지 확인하세요.

    원인: 환경 변수가 전달되지 않은 경우
    해결: docker run 시 -e 옵션으로 모든 환경 변수를 전달했는지 확인하세요.
          또는 --env-file 옵션을 사용하세요:
          docker run --env-file env.env ...

    원인: 메모리 부족
    해결: Dockerfile의 -Xmx384m을 늘려보세요.
          최소 512MB 이상의 컨테이너 메모리를 확보하세요.
