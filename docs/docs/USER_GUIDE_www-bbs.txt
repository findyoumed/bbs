================================================================================
  1. 프로젝트 개요
================================================================================

  이 프로젝트는 1990년대 PC통신(BBS) 환경을 웹 브라우저에서 재현한
  "웹 터미널 BBS"입니다.

  - 80x24 고정 해상도의 터미널 화면을 Canvas 위에 렌더링합니다.
  - 키보드 입력으로 명령어를 수행하는 CLI 방식의 인터페이스입니다.
  - 게시판, 실시간 채팅, 뉴스/날씨 등 PC통신의 주요 기능을 제공합니다.
  - 백엔드 저장소로 Supabase(PostgreSQL)를 사용합니다.
  - Vercel에 서버리스로 배포할 수 있습니다.


================================================================================
  2. 사전 준비 사항
================================================================================

  2-1. 필수 소프트웨어

    - Node.js 18 이상 (권장: 20 LTS)
      확인 방법: node --version

    - npm (Node.js 설치 시 함께 포함됨)
      확인 방법: npm --version

  2-2. 필수 외부 서비스

    - Supabase 프로젝트 (https://supabase.com)
      게시판 데이터, 사용자 인증, 실시간 채팅에 사용됩니다.
      프로젝트 생성 후 다음 정보가 필요합니다:
        - Supabase URL
        - Anon Key (또는 Publishable Key)
        - Service Role Key
        - Database Password

  2-3. 선택 사항

    - Vercel CLI (배포 시 필요)
      설치: npm install -g vercel


================================================================================
  3. 설치 및 실행
================================================================================

  3-1. 프로젝트 클론 및 의존성 설치

    git clone [저장소 URL]
    cd www-bbs
    npm install

  3-2. 환경 변수 설정

    프로젝트 루트에 .env 파일을 생성합니다.
    (4장 "환경 변수" 참조)

  3-3. 로컬 서버 실행

    npm start

    또는 개발 중 자동 재시작을 원할 경우:

    npx nodemon server.js

    서버가 시작되면 터미널에 다음과 같이 출력됩니다:

    Server: http://localhost:3000/
    Board repository: supabase

  3-4. 브라우저에서 접속

    웹 브라우저를 열고 다음 주소로 접속합니다:

    http://localhost:3000/

    검은 화면에 BBS 터미널이 나타나면 성공입니다.

  3-5. 빌드 (배포 전)

    npm run build

    이 명령은 src 디렉토리의 클라이언트 소스를
    public/src 디렉토리로 복사합니다.


================================================================================
  4. 환경 변수 (.env) 설정
================================================================================

  프로젝트 루트에 .env 파일을 만들고 다음 값들을 설정합니다.

  주의: .env 파일은 .gitignore에 포함되어 있으므로
        절대로 Git에 커밋되지 않습니다. 비밀키가 포함되어 있으므로
        외부에 노출되지 않도록 주의하세요.

  --------------------------------------------------------------------------
  필수 항목
  --------------------------------------------------------------------------

  BOARD_REPOSITORY_DRIVER=supabase
    게시판 저장소 종류를 지정합니다.
    "supabase"로 설정하면 Supabase 데이터베이스를 사용합니다.

  SUPABASE_URL=https://[프로젝트ID].supabase.co
    Supabase 프로젝트의 API URL입니다.
    Supabase 대시보드 > Settings > API 에서 확인할 수 있습니다.

  SUPABASE_ANON_KEY=[키값]
    Supabase의 공개용 Anon Key입니다.
    클라이언트(브라우저)에서 Supabase에 접속할 때 사용됩니다.

  SUPABASE_SERVICE_ROLE_KEY=[키값]
    Supabase의 서비스 역할 키입니다.
    서버 측에서 관리자 권한으로 Supabase에 접근할 때 사용됩니다.
    절대로 브라우저에 노출시키면 안 됩니다.

  PORT=3000
    로컬 개발 서버의 포트 번호입니다.
    기본값은 3002이며, 원하는 포트로 변경할 수 있습니다.

  --------------------------------------------------------------------------
  선택 항목
  --------------------------------------------------------------------------

  SUPABASE_BOARDS_TABLE=boards
    Supabase에서 게시판 테이블의 이름입니다. 기본값: boards

  SUPABASE_POSTS_TABLE=posts
    Supabase에서 게시글 테이블의 이름입니다. 기본값: posts

  SUPABASE_ATTACHMENTS_TABLE=attachments
    Supabase에서 첨부파일 테이블의 이름입니다. 기본값: attachments

  SUPABASE_RECOMMENDATIONS_TABLE=post_recommendations
    Supabase에서 추천 테이블의 이름입니다. 기본값: post_recommendations

  SUPABASE_DB_PASSWORD=[비밀번호]
    Supabase 데이터베이스 비밀번호입니다.

  DATABASE_URL=postgresql://postgres:[비밀번호]@db.[프로젝트ID].supabase.co:5432/postgres
    PostgreSQL 직접 연결 URL입니다.

  BBS_ADMIN_USER_IDS=[사용자ID1],[사용자ID2]
    운영자 권한을 부여할 사용자 ID 목록입니다. 쉼표로 구분합니다.

  BBS_ADMIN_EMAILS=[이메일1],[이메일2]
    운영자 권한을 부여할 이메일 목록입니다. 쉼표로 구분합니다.

  BBS_HOST_NAME=나의BBS
    BBS 상단에 표시되는 호스트명(BBS 이름)입니다.
    legacy 설정 파일의 <name> 태그로도 설정할 수 있습니다.

  BBS_LEVEL_ALIASES=1:일반회원;2:특별회원;99:운영자
    회원 레벨별 표시 이름을 커스터마이징합니다.
    형식: "레벨숫자:표시이름" 을 세미콜론(;)이나 쉼표(,)로 구분합니다.

  LEGACY_SETTINGS_PATH=[경로]
    레거시 설정 파일(hanulso.cfg 등)의 절대 경로입니다.
    기본값: 프로젝트루트/legacy/hanulso.cfg


================================================================================
  5. 레거시 설정 파일
================================================================================

  legacy 디렉토리에는 BBS의 메뉴 구조와 텍스트 자산(Asset)이 저장됩니다.

  5-1. 메뉴 파일 (*.mnu)

    legacy/hanulso.mnu
      BBS 전체 메뉴 트리 구조가 정의된 XML 파일입니다.
      이 파일의 내용이 BBS 메인 화면의 메뉴와 GO 명령에 반영됩니다.

    legacy/news.mnu
      뉴스 서비스의 신문사/카테고리 목록이 정의된 파일입니다.

    legacy/weather.mnu
      날씨 서비스의 지역 목록이 정의된 파일입니다.

  5-2. 텍스트 자산 파일 (legacy/txt/)

    top.txt
      메인 화면 상단에 표시되는 ANSI 아트나 환영 메시지입니다.

    header.txt
      게시판 목록 상단에 표시되는 커스텀 헤더입니다.

    footer.txt
      게시판 목록 하단에 표시되는 광고나 안내 문구입니다.

    article_footer.txt
      게시글 읽기 화면 하단에 표시되는 안내 문구입니다.

    chatt_footer.txt
      대화방 화면 하단에 표시되는 안내 문구입니다.

    help.txt
      도움말 원본 자산입니다.
      다만 실제 C/H 도움말 화면은 /api/assets/help.txt 요청 시
      src/server/createRequestHandler.js 에서 동적으로 생성됩니다.

    register.txt
      회원 가입 안내 문구입니다.

    pass.txt
      비밀번호 관련 안내 문구입니다.

    life_info.txt
      생활 정보 하위 메뉴의 안내 화면입니다.

    pds_prog.txt, pds_game.txt, pds_sound.txt, pds_special.txt
      각 자료실 하위 메뉴의 안내 화면입니다.

    levelup_header.txt, levelup_footer.txt
      특선회원 신청 게시판의 헤더/풋터입니다.

    adlib_data_footer.txt, midi_data_footer.txt
      각 게시판별 커스텀 풋터 파일입니다.

  5-3. 텍스트 자산의 게시판별 매핑

    메뉴 파일(hanulso.mnu)에서 각 게시판에 header, footer 속성을
    지정하면 해당 파일이 게시판 화면에 표시됩니다.
    예: <header>levelup_header.txt</header>

================================================================================
  7. 터미널 사용법 (일반 사용자)
================================================================================

  BBS 터미널에 접속하면 검은 화면에 메인 메뉴가 표시됩니다.
  화면 맨 아래 줄에 "입력>" 프롬프트가 나타나며,
  여기에 명령어를 입력하고 Enter를 누르면 실행됩니다.

  --------------------------------------------------------------------------
  7-1. 기본 명령어
  --------------------------------------------------------------------------

  숫자 입력      해당 번호의 메뉴 항목을 선택합니다.
                 예: 1 을 입력하면 "공지사항" 게시판에 진입합니다.

  T              초기 화면(메인 메뉴)으로 돌아갑니다.
                 어디에서든 T를 입력하면 처음으로 돌아갑니다.

  P 또는 M       이전 화면 또는 상위 메뉴로 돌아갑니다.

  C 또는 H       도움말을 표시합니다.
                 현재 화면에서 사용할 수 있는 명령어 목록을 보여줍니다.

  GO [이름]      특정 메뉴나 게시판으로 바로 이동합니다.
                 예: GO plaza    -> 자유 게시판으로 바로 이동
                 예: GO chat     -> 대화방으로 바로 이동
                 예: GO weather  -> 날씨 정보로 바로 이동
                 예: GO news     -> 뉴스로 바로 이동

  GO             GO 명령으로 이동 가능한 전체 목록을 표시합니다.

  WHO [아이디]   해당 사용자의 프로필 정보를 조회합니다.
                 예: WHO john123  -> john123 회원의 프로필 보기

  USER           현재 접속 중인 활동 사용자 목록을 표시합니다.

  SYS            시스템 정보(호스트, 플랫폼, 메모리, 디스크 등)를 표시합니다.

  XX             메모함(쪽지함)을 엽니다.

  SYSOP          운영자 메뉴를 엽니다. (운영자 전용)

  BIO            바이오리듬을 확인합니다.
                 생일 정보가 등록되어 있어야 합니다.

  LUCK           오늘의 운세를 확인합니다.
                 생일 정보가 등록되어 있어야 합니다.

  X 또는 BYE     BBS를 종료합니다.
                 브라우저 환경에서는 탭을 닫거나 초기 화면으로 돌아갑니다.

  --------------------------------------------------------------------------
  7-2. 게시판 사용법
  --------------------------------------------------------------------------

  메인 메뉴에서 번호를 입력하거나, GO [게시판ID]로 게시판에 진입합니다.

  게시판에 들어가면 게시글 목록이 표시됩니다.
  각 게시글은 번호, 작성자, 날짜, 조회수, 추천수, 제목이 표시됩니다.

  게시판 목록 화면의 명령어:

  [번호]         해당 번호의 게시글을 읽습니다.
                 예: 3  -> 3번 게시글 읽기

  Enter 또는 F   다음 페이지로 이동합니다.

  B              이전 페이지로 이동합니다.

  L              첫 페이지로 돌아가며, 검색 상태가 있으면 해제합니다.

  W              새 게시글을 작성합니다.
                 제목 입력 후 터미널 에디터가 열립니다.

  LT [검색어]    제목+본문으로 검색합니다.
                 예: LT 안녕  -> 제목이나 본문에 "안녕"이 포함된 글 검색

  LI [검색어]    작성자(아이디/닉네임)로 검색합니다.
                 현재 구조에서는 닉네임이 아이디와 동일하게 취급됩니다.
                 예: LI admin  -> admin이 쓴 글 검색

  ED [번호]      해당 번호의 게시글을 수정합니다.
                 본인이 작성한 글만 수정할 수 있습니다.

  DD [번호]      해당 번호의 게시글을 삭제합니다.
                 본인이 작성한 글 또는 운영자만 삭제 가능합니다.

  P 또는 M       이전 화면(메인 메뉴 등)으로 돌아갑니다.

  --------------------------------------------------------------------------
  7-3. 게시글 읽기/쓰기
  --------------------------------------------------------------------------

  게시글 읽기 화면에서 사용할 수 있는 명령어:

  Enter          다음 페이지로 스크롤합니다.

  B              이전 페이지로 스크롤합니다.

  A              다음 게시글을 읽습니다. (최신 글 방향)

  N              이전 게시글을 읽습니다. (오래된 글 방향)

  P 또는 M       직전 게시글 목록으로 돌아갑니다.
                 이전에 보고 있던 페이지와 검색 상태를 복원합니다.

  L              현재 게시판의 첫 페이지 목록으로 돌아갑니다.

  RE             현재 게시글에 답변(댓글)을 작성합니다.

  ED             현재 게시글을 수정합니다.
                 본인이 작성한 글만 수정할 수 있습니다.

  DD             현재 게시글을 삭제합니다.
                 첨부 파일이 있는 경우 첨부 삭제와 게시글 삭제 중 선택할 수 있습니다.

  OK             현재 게시글을 추천합니다.
                 한 게시글에 대해 1회만 추천 가능합니다.

  LA             해당 게시글의 첨부 파일 전체 목록을 표시합니다.

  NA / PA        첨부 파일 목록이 여러 묶음일 때 다음 / 이전 묶음을 봅니다.

  UP             현재 게시글에 파일을 첨부(업로드)합니다.
                 파일 선택 대화상자가 열립니다.

  DN [번호]      해당 번호의 첨부 파일을 다운로드합니다.

  PR             현재 게시글을 인쇄 가능한 형태로 새 창에 엽니다.

  게시글 작성 / 수정 / 답글 작성:

  제목을 입력한 뒤 터미널 에디터에 진입합니다.
  본문을 자유롭게 입력한 뒤:

  Ctrl+C         저장합니다.
  Esc            작성을 취소합니다.
  Enter          줄바꿈을 입력합니다.

  --------------------------------------------------------------------------
  7-4. 대화방 (채팅)
  --------------------------------------------------------------------------

  메인 메뉴에서 대화방 번호를 선택하거나 GO chat 으로 접속합니다.

  대화방 목록 화면에서의 명령어:

  [번호]         해당 번호의 대화방에 참여합니다.

  O              새 대화방을 개설합니다.
                 방 제목, 비밀번호(선택), 최대 인원을 입력합니다.

  Enter 또는 F   다음 페이지

  B              이전 페이지

  L              첫 페이지로 돌아갑니다.

  P 또는 M       이전 화면으로 돌아갑니다.

  대화방 안에서의 명령어:

  [문자열]       메시지를 입력하면 전송됩니다.
  /Q 또는 /QUIT  대화방을 나가고 이전 화면으로 돌아갑니다.
  UP / DN        이전 대화 / 다음 대화 방향으로 화면을 이동합니다.
  T              메인 화면으로 돌아갑니다.

  대화방은 Supabase Realtime을 이용하여 실시간으로 메시지가 주고받아집니다.
  대화 상대방의 메시지는 자동으로 화면에 표시됩니다.

  --------------------------------------------------------------------------
  7-5. 서비스 메뉴 (날씨, 뉴스)
  --------------------------------------------------------------------------

  날씨 정보:
    GO weather 또는 메인 메뉴 > 생활 정보 > 기상 정보
    지역 목록이 표시되며, 번호를 선택하면 해당 지역의 날씨가 표시됩니다.

  뉴스:
    GO news 또는 메인 메뉴 > 생활 정보 > 뉴스
    신문사 목록 > 카테고리 선택 > 기사 목록 > 기사 읽기 순서로 탐색합니다.
    뉴스는 RSS 피드를 통해 실시간으로 가져옵니다.

  서비스 화면 공통 명령어:
    [번호]       항목을 선택합니다.
    Enter 또는 F  다음 페이지
    B            이전 페이지
    L            첫 페이지로 돌아갑니다.
    P 또는 M    이전 화면으로 돌아갑니다.
    PR           현재 내용을 인쇄합니다.

  --------------------------------------------------------------------------
  7-6. 메모함
  --------------------------------------------------------------------------

  XX 명령으로 메모함을 엽니다.
  받은 메모 목록이 표시되며, 읽지 않은 메모는 [N] 표시가 붙습니다.

  메모함 목록에서의 명령어:

  [번호]         해당 번호의 메모를 읽습니다.

  W 또는 RE      새 메모를 작성합니다.
                 받는 사람 ID, 제목, 본문을 입력합니다.

  DD [번호]      메모를 삭제합니다.

  Enter 또는 F   다음 페이지
  B              이전 페이지
  L              첫 페이지로 돌아갑니다.
  P 또는 M       이전 화면으로 돌아갑니다.

  메모 읽기 화면에서:

  Enter          다음 페이지
  B              이전 페이지
  RE 또는 W      해당 메모에 답장합니다.
  DD             해당 메모를 삭제합니다.
  OK             메모 목록으로 돌아갑니다.
  P 또는 M       이전 화면으로 돌아갑니다.
  PR             현재 메모를 인쇄합니다.

  --------------------------------------------------------------------------
  7-7. 회원 정보 보기와 내 정보
  --------------------------------------------------------------------------

  WHO [아이디] 명령으로 다른 사용자의 프로필을 조회합니다.

  표시 정보:
    아이디, 닉네임, 레벨, 이메일, 생일, 성별, 가입일, 최근접속

  터미널 기본 명령 체계에는 별도의 "내 정보 수정" 명령이 없습니다.
  자신의 비밀번호, 닉네임, 생일, 이메일, 성별 수정은
  POST /api/members/profile API를 통해 처리합니다.

  API에서 수정 가능한 항목:
    [1] 비밀번호   - 영문과 특수문자를 섞어 6자 이상
    [2] 닉네임     - 다른 사용자에게 표시되는 이름
    [3] 생일       - YYYY-M-D 형식 (예: 1990-1-15)
    [4] 이메일     - 이메일 주소
    [5] 성별       - 남성(1) 또는 여성(2)
    [0] 그만       - 수정을 취소합니다.

  --------------------------------------------------------------------------
  7-8. 부가 기능
  --------------------------------------------------------------------------

  BIO (바이오리듬):
    등록된 생일을 기준으로 오늘의 바이오리듬을 계산합니다.
    - 신체 리듬 (23일 주기)
    - 감정 리듬 (28일 주기)
    - 지성 리듬 (33일 주기)
    각 항목은 -100 ~ +100 사이의 점수와 상태(상승/하강/전환)를 표시합니다.
    사용 전 생일 정보를 먼저 등록해야 합니다.

  LUCK (오늘의 운세):
    등록된 생일과 성별을 기반으로 오늘의 운세를 생성합니다.
    - 오늘의 운세 메시지
    - 행운 숫자
    - 행운 색상
    - 유리한 방향
    - 컨디션 메모
    매일 다른 결과가 나타납니다.
    사용 전 생일 정보를 먼저 등록해야 합니다.


================================================================================
  8. 터미널 사용법 (운영자)
================================================================================

  운영자는 .env 파일의 BBS_ADMIN_USER_IDS 또는 BBS_ADMIN_EMAILS에
  등록된 사용자입니다. 또는 레거시 설정 파일(hanulso.cfg)의
  <sysop> 태그에 등록된 사용자입니다.

  --------------------------------------------------------------------------
  8-1. 운영자 메뉴 (SYSOP)
  --------------------------------------------------------------------------

  SYSOP 명령으로 운영자 전용 메뉴에 접근합니다.

  메뉴 항목:

  [1] 회원 검색
      - 아이디로 닉네임을 찾거나, 닉네임으로 아이디를 찾을 수 있습니다.

  [2] 회원 정보 변경
      - 회원 레벨 변경: 지정한 회원의 레벨(등급)을 변경합니다.
      - 회원 비밀번호 변경: 지정한 회원의 비밀번호를 초기화합니다.

  [3] 회원 삭제
      - 지정한 회원 ID의 계정을 삭제합니다.

  [4] 게시물 삭제
      - 게시판 ID와 게시글 번호를 입력하여 특정 게시물을 삭제합니다.

  [5] 활동 사용자 보기
      - USER 명령과 동일합니다.

  [6] 시스템 정보 보기
      - SYS 명령과 동일합니다.

  [7] 메모함 열기
      - XX 명령과 동일합니다.

  --------------------------------------------------------------------------
  8-2. 게시글 내 운영자 명령
  --------------------------------------------------------------------------

  운영자가 게시글을 읽고 있는 상태에서 추가로 사용할 수 있는 명령어:

  SETLV          해당 게시글 작성자의 회원 레벨을 변경합니다.
                 레벨 번호를 입력하면 즉시 변경됩니다.

  DD             운영자는 다른 사용자의 게시글도 삭제할 수 있습니다.

  회원 레벨 체계:
    레벨은 .env의 BBS_LEVEL_ALIASES 또는 레거시 설정 파일에서
    커스터마이징할 수 있습니다.
    기본값:
      1   일반회원
      2   특별회원
      99  운영자


================================================================================
  9. URL 라우팅
================================================================================

  이 BBS는 SPA(Single Page Application) 방식으로 작동하며,
  URL 경로를 통해 특정 화면에 직접 접근할 수 있습니다.

  기본 URL 형식:

  /                              메인 화면
  /board/[게시판ID]              게시판 글 목록
  /board/[게시판ID]?page=2       게시판 글 목록 2페이지
  /board/[게시판ID]/[글번호]     특정 게시글
  /chat                          대화방
  /service/weather               날씨 서비스
  /service/weather/[지역]        특정 지역 날씨
  /service/news                  뉴스 서비스
  /service/news/[신문사]         뉴스 카테고리
  /service/news/[신문사]/[카테고리]           기사 목록
  /service/news/[신문사]/[카테고리]/[번호]    기사 읽기
  /memos                         메모함
  /memos/[메모번호]              메모 읽기
  /sysop                         운영자 메뉴

  브라우저의 뒤로가기, 앞으로가기, 새로고침이 모두 지원됩니다.
  URL을 직접 입력하여 특정 게시글이나 서비스로 바로 접근할 수 있습니다.


================================================================================
 10. 폰트 및 화면 구성
================================================================================

  이 BBS는 PC통신 느낌을 제대로 살리기 위해
  "하이브리드 폰트 전략"을 사용합니다.

  화면 규격:
    - 가로 80칸 x 세로 24줄 (640x384 픽셀)
    - 한글 1글자 = 2칸, 영문/숫자/공백 1글자 = 1칸 (2:1 비율)

  폰트 전략 (style.css에 정의):

    1순위: BbsHybridFont (오리지널 둥근모)
      - 한글 전용 (unicode-range: U+AC00-D7A3 등)
      - CDN: projectnoonnu DungGeunMo.woff

    2순위: BbsLineFont (굴림체)
      - 선 기호 전용 (가로선, 세로선, 모서리, 블록 등)
      - unicode-range: U+002D, U+007C, U+2500-257F, U+2580-259F
      - 시스템 로컬 폰트 (local('GulimChe'))

    3순위: Sam3KRFont (삼국지 폰트)
      - 영문, 숫자, 공백, 기타 모든 문자 담당
      - 완벽한 2:1 고정폭 비율 보장
      - CDN: projectnoonnu Sam3KRFont.woff

    4순위: GulimChe (시스템 보험)
      - 웹폰트가 모두 실패했을 때의 대비용

    5순위: monospace (최후의 보루)
      - 최후의 폴백

  이 순서 덕분에:
    - 한글은 예쁜 둥근모 디자인으로 표시됩니다.
    - 선 기호는 굴림체의 얇고 깨끗한 라인으로 표시됩니다.
    - 공백과 나머지 문자는 삼국지 폰트의 정밀한 격자로 표시되어
      세로줄이 일직선으로 완벽하게 정렬됩니다.


================================================================================
 11. 배포 (Vercel)
================================================================================

  이 프로젝트는 Vercel에 서버리스로 배포할 수 있습니다.

  11-1. 사전 준비

    Vercel CLI 설치:
      npm install -g vercel

    Vercel 계정 로그인:
      vercel login

  11-2. 빌드

    npm run build

    이 명령은 src 디렉토리의 클라이언트 소스를
    public/src 디렉토리로 복사합니다.

  11-3. 배포

    vercel --prod

    또는 GitHub 저장소와 연결하면 push 시 자동 배포됩니다.

  11-4. 환경 변수 설정

    Vercel 대시보드 > 프로젝트 설정 > Environment Variables에서
    .env 파일의 모든 값을 등록해야 합니다.

    특히 다음 값은 반드시 등록해야 합니다:
      - BOARD_REPOSITORY_DRIVER
      - SUPABASE_URL
      - SUPABASE_ANON_KEY
      - SUPABASE_SERVICE_ROLE_KEY

  11-5. 라우팅 설정 (vercel.json)

    vercel.json 파일에 다음과 같은 SPA 리라이트 규칙이 설정되어 있습니다:
      /board/* -> /index.html
      /chat/*  -> /index.html
      /service/* -> /index.html

    이 설정 덕분에 브라우저에서 직접 URL을 입력해도
    올바른 화면이 표시됩니다.


================================================================================
 12. 테스트 스크립트
================================================================================

  package.json에 정의된 테스트 스크립트 목록입니다.
  모든 스크립트는 프로젝트 루트에서 npm run [이름]으로 실행합니다.

  npm run check
    Supabase 연결 상태를 확인합니다.
    테이블 존재 여부, RLS 정책 등을 검증합니다.

  npm run smoke:boards
    게시판 CRUD(생성, 읽기, 수정, 삭제) 기능을 테스트합니다.

  npm run smoke:command-parity
    모든 터미널 명령어의 파싱 및 실행을 테스트합니다.

  npm run smoke:renderer-ui
    터미널 렌더러의 UI 렌더링을 테스트합니다.

  npm run smoke:ui-geometry
    80x24 터미널의 기하학적 정렬을 테스트합니다.

  npm run smoke:ui-layout
    각 화면(게시판, 채팅, 서비스)의 레이아웃을 테스트합니다.

  npm run smoke:printable-view

 13. API 엔드포인트 목록
================================================================================

  서버가 제공하는 REST API 목록입니다.
  모든 경로는 /api/ 접두사로 시작합니다.

  --------------------------------------------------------------------------
  메뉴 및 시스템
  --------------------------------------------------------------------------

  GET  /api/menu                 메뉴 트리 전체를 반환합니다.

  --------------------------------------------------------------------------
  인증
  --------------------------------------------------------------------------

  GET  /api/auth/config          Supabase 인증 설정(URL, Key)을 반환합니다.
  POST /api/auth/session         세션 정보를 처리합니다.

  --------------------------------------------------------------------------
  게시판
  --------------------------------------------------------------------------

  GET  /api/boards               전체 게시판 목록을 반환합니다.
  GET  /api/boards/meta          저장소 메타 정보를 반환합니다.
  GET  /api/boards/[ID]          특정 게시판의 게시글 목록을 반환합니다.
       쿼리파라미터: page, pageSize, lt(제목/본문), li(작성자)
       터미널 명령어 LT / LI 는 각각 이 검색 모드와 대응합니다.

  GET  /api/boards/[ID]/posts/[번호]       특정 게시글을 반환합니다.
  POST /api/boards/[ID]/posts              새 게시글을 작성합니다.
  PATCH /api/boards/[ID]/posts/[번호]      게시글을 수정합니다.
  DELETE /api/boards/[ID]/posts/[번호]     게시글을 삭제합니다.
  POST /api/boards/[ID]/posts/[번호]/reply      답변을 작성합니다.
  POST /api/boards/[ID]/posts/[번호]/recommend  게시글을 추천합니다.

  --------------------------------------------------------------------------
  첨부파일
  --------------------------------------------------------------------------

  GET    /api/boards/[ID]/posts/[번호]/attachments           첨부파일 목록
  POST   /api/boards/[ID]/posts/[번호]/attachments           첨부파일 업로드
  GET    /api/boards/[ID]/posts/[번호]/attachments/[ID]/download  다운로드
  DELETE /api/boards/[ID]/posts/[번호]/attachments/[ID]      첨부파일 삭제

  --------------------------------------------------------------------------
  회원
  --------------------------------------------------------------------------

  GET  /api/members/[ID]              회원 프로필 조회
  GET  /api/members/search?nickName=  닉네임으로 회원 검색
  POST /api/members/profile           내 프로필 수정
  POST /api/members/[ID]/level        회원 레벨 변경 (운영자)
  POST /api/members/[ID]/password     회원 비밀번호 변경
  DELETE /api/members/[ID]            회원 삭제 (운영자)

  --------------------------------------------------------------------------
  메모 (쪽지)
  --------------------------------------------------------------------------

  GET    /api/memos                메모 목록
  POST   /api/memos                메모 보내기
  GET    /api/memos/[ID]           메모 읽기
  POST   /api/memos/[ID]/read      메모 읽음 처리
  DELETE /api/memos/[ID]           메모 삭제

  GET  /api/services/news                 뉴스 신문사 목록
  GET  /api/services/news/[신문사]        뉴스 카테고리

  --------------------------------------------------------------------------

 14. 문제 해결 (트러블슈팅)
================================================================================

  14-1. 서버가 시작되지 않는 경우

    원인: .env 파일이 없거나 설정값이 잘못된 경우
    해결: .env 파일이 프로젝트 루트에 존재하는지 확인하세요.
          SUPABASE_URL, SUPABASE_ANON_KEY 등이 올바른지 확인하세요.

    원인: node_modules가 설치되지 않은 경우
    해결: npm install 을 실행하세요.

    원인: 포트가 이미 사용 중인 경우
    해결: .env의 PORT 값을 다른 번호(예: 3001)로 변경하세요.

  14-2. 화면이 표시되지 않는 경우

    원인: index.html이 로드되지 않는 경우
    해결: http://localhost:3000/ 으로 접속했는지 확인하세요.
          public/index.html 파일이 존재하는지 확인하세요.

    원인: 클라이언트 JS가 빌드되지 않은 경우
    해결: npm run build 를 실행하여 public/src에 파일을 복사하세요.

  14-3. 폰트가 깨지거나 정렬이 어긋나는 경우

    원인: CDN에서 웹폰트를 불러오지 못하는 경우
    해결: 인터넷 연결을 확인하세요.
          style.css의 CDN URL이 올바른지 확인하세요.
          브라우저 개발자 도구(F12) > Network 탭에서
          woff 파일의 응답 코드가 200인지 확인하세요.

    원인: 공백이나 선 기호의 너비가 맞지 않는 경우
    해결: style.css의 letter-spacing: 0px, word-spacing: 0px가
          적용되어 있는지 확인하세요.

  14-4. 게시판 데이터가 표시되지 않는 경우

    원인: Supabase 연결 실패
    해결: npm run check 를 실행하여 연결 상태를 확인하세요.
          .env의 SUPABASE_URL, SUPABASE_ANON_KEY,
          SUPABASE_SERVICE_ROLE_KEY가 올바른지 확인하세요.

    원인: 테이블이 생성되지 않은 경우
    해결: Supabase 대시보드에서 boards, posts, attachments,
          post_recommendations 테이블이 존재하는지 확인하세요.

  14-5. 로그인이 되지 않는 경우

    원인: Supabase Auth 설정 문제
    해결: Supabase 대시보드 > Authentication > Settings에서
          이메일/비밀번호 인증이 활성화되어 있는지 확인하세요.
          Site URL이 올바르게 설정되어 있는지 확인하세요.

  14-6. 대화방이 작동하지 않는 경우

    원인: Supabase Realtime 비활성화
    해결: Supabase 대시보드 > Database > Realtime에서
          해당 테이블의 Realtime이 활성화되어 있는지 확인하세요.

    원인: Realtime 연결 실패
    해결: 브라우저 개발자 도구의 Console 탭에서
          WebSocket 관련 오류 메시지를 확인하세요.

  14-7. Vercel 배포 후 작동하지 않는 경우

    원인: 환경 변수 미등록
    해결: Vercel 대시보드 > Settings > Environment Variables에서
          모든 .env 값이 등록되어 있는지 확인하세요.

    원인: 빌드 누락
    해결: 로컬에서 npm run build 실행 후 다시 배포하세요.
          npm run smoke:vercel-ready 로 배포 준비 상태를 확인하세요.
